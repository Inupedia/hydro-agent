# Hydro-Agent 开源数据源与实验数据协议

**状态：** 课题数据设计与实现约束

**目标：** 明确 Hydro-Agent 首期单流域、日尺度 lead 1/2/3 预报所采用的公开数据源、R/F 两种 forcing 模式、XAJ 与 OpenHydroNet 的输入映射，以及防止时间泄漏的数据可用性规则。

> 本文件不是“数据源推荐清单”，而是 C0 数据底座、B/F/E 阶段隔离和正式实验的执行协议。实现时任何进入模型、Agent、Evaluator 的数据都必须能够说明：**它来自哪里、在什么时间可获得、属于哪一个快照、允许在哪个阶段使用。**

---

## 1. 结论与首期选择

当前公开数据足以支撑本课题做成真实可运行系统，而不是仅做概念验证。

首期建议固定 **South Fork Payette River at Lowman, Idaho（USGS 13235000 / `camels_13235000`）** 作为主实验流域。原因：

1. USGS 提供长期公开流量观测，可作为 target 与评价真值；
2. CAMELS / Caravan 提供流域边界、面积及静态属性；
3. OpenHydroNet 官方教程使用 `camels_13235000` 作为局部微调示例，接口风险低；
4. Caravan MultiMet 提供与 FloodHub-style OpenHydroNet 直接兼容的多源历史/预报气象 forcing；
5. XAJ 所需降水、PET、流量和流域面积均可由公开数据获得；
6. 单流域按时间和变量按需读取，适合 M1 Pro 的课题计算条件。

首期数据路线：

```text
Basin / Static        CAMELS / Caravan
Observed Streamflow   USGS
R-mode Meteorology    ERA5-Land / Caravan historical forcing
OHN F-mode Forecast   Caravan MultiMet: HRES / GraphCast
XAJ F-mode Forecast   GEFS Reforecast（扩展；P + forecast-derived PET）
```

## 2. 两种 forcing 模式必须严格区分

### 2.1 R：理想气象驱动回算

`forcing_mode = R`

允许使用目标时刻以后最终形成的再分析或实测气象资料，例如 ERA5-Land。它适合验证：

- 数据检查与修复；
- XAJ 率定和参数优化机制；
- OpenHydroNet 推理/局部适配工程能力；
- Agent Loop 是否能根据 Evidence 改变下一动作；
- O/P/A 方法机制对照。

R 模式不能宣称“真实历史提前预报”。

```text
issue_time = T

historical state ≤ T
future forcing > T may come from reanalysis
        ↓
Hydrological Model
        ↓
lead 1/2/3 reconstruction
```

### 2.2 F：历史真实起报回放

`forcing_mode = F`

对于 `issue_time = T`，所有模型输入必须满足：

```text
available_at <= T
```

未来 lead forcing 必须来自在 T 时刻已经发布或理论上已经可获得的天气预报，而不能使用事后再分析替代。

```text
issue_time = T

observations available by T
        +
forecast issued by T for T+1 ... T+3
        ↓
Hydrological Model
        ↓
Historical forecast replay
```

F 是课题最终希望具备的严格 historical replay 模式。

## 3. 数据源矩阵

| 数据源 | 主要内容 | 本课题用途 | R | F | 首期优先级 |
|---|---|---|---:|---:|---:|
| USGS Water Data | 日/连续流量、站点信息 | target、当前流量、评价真值 | ✅ | ✅* | P0 |
| CAMELS | 流域属性、边界、历史水文气象数据 | basin metadata、XAJ/OHN 辅助 | ✅ | 部分 | P0 |
| Caravan | 全球统一流域数据、streamflow、static attributes | OHN target/statics、统一对象 | ✅ | 部分 | P0 |
| Caravan MultiMet | HRES、GraphCast、CPC、IMERG 等多源 forcing | OHN hindcast/forecast forcing | ✅ | ✅ | P0 |
| ERA5-Land | 再分析降水、温度、辐射等 | R 模式气象、PET/状态重建 | ✅ | ❌ 作为未来 forcing | P0 |
| NOAA GEFS Reforecast | 历史天气预报 | XAJ 严格 F 模式 P + PET 派生 | 可 | ✅ | P1 |

`*`：USGS 观测在 F 阶段只能使用 `available_at <= issue_time` 的部分；未来实测流量只允许在 E 评价阶段读取。

## 5. OpenHydroNet 数据协议

### 5.1 官方数据路径

OpenHydroNet / Google FloodHub-style Mean Embedding Forecast LSTM 的公开配置使用：

```text
targets      = Caravan
statics      = Caravan
dynamics     = Caravan MultiMet
hindcast     = HRES + GraphCast + IMERG + CPC (+ fallback)
forecast     = HRES + GraphCast
```

首期应优先复用这一路径，不自行创造新的 feature set。

### 5.2 首期 F 模式

对于每个 `issue_time`：

1. 取该时刻以前可用的 hindcast inputs；
2. 取对应起报时间可用的 HRES / GraphCast future inputs；
3. 只预测 lead 1/2/3；
4. 保存 forecast issue/release 信息和数据快照引用；
5. 不允许用 ERA5-Land 的未来实际天气填补“当时未知”的 future forecast，除非明确将该任务标记为 R。

### 5.3 预训练权重时间泄漏

当前公开 FloodHub-style 预训练权重训练覆盖 **1982–2023**，且没有严格 temporal holdout。

因此：

```text
禁止：
pretrained OHN + 1982–2023 historical evaluation
→ 宣称独立泛化性能
```

允许：

```text
A. post-2023 forward evaluation

或

B. 为正式 O/P/A 实验自行建立时间隔离 baseline：
   Train      < Validation < Test
```

推荐正式实验采用 B；Google pretrained 权重用于工程复现、迁移学习或补充实验。

### 5.4 OHN 时间切分示例

正式日期需在 G0 根据 MultiMet 实际覆盖和样本量锁定，示意：

```text
Training       2000–2018
Validation     2019–2021
Test / Replay  2022–2024
```

要求：

- Test 不参与权重训练；
- Test 不参与阈值调节；
- Test 不参与 Agent Prompt / Skill / 策略修改；
- E 阶段打开 test observation 后只允许评价。

## 6. XAJ 数据协议

XAJ 首期输入至少包括：

```text
P    precipitation
PET  potential evapotranspiration
Q    observed streamflow（率定/验证/评价）
A    basin area
```

### 6.1 R 模式

首期优先先跑通：

```text
P / meteorology  ← ERA5-Land / Caravan
PET              ← 合法公开 PET 或由冻结方法计算
Q                ← USGS
A                ← CAMELS / Caravan
```

这足够完成：

- XAJ baseline；
- bounded calibration；
- parameter optimization；
- Gate / rollback；
- Agent 是否应继续调参的机制验证。

### 6.2 F 模式的 PET 问题

严格 F 模式不能在 `issue_time = T` 时使用未来 T+1...T+3 的 ERA5-Land PET，因为它属于事后资料。

推荐 P1 路线：

```text
NOAA GEFS Reforecast
  ├── forecast precipitation
  ├── temperature
  ├── humidity / dew point
  ├── wind
  ├── pressure
  └── radiation
          ↓
冻结的 PET 计算方法
例如 FAO Penman–Monteith
          ↓
forecast PET
          ↓
XAJ F-mode
```

在 GEFS/PET 路径完成以前：

- XAJ 可以作为正式 R 模式模型；
- 不得把使用未来再分析 PET 的 XAJ 结果标记成严格 F 模式。

## 7. `available_at` 是整个数据协议的核心字段

每一个进入系统的数据快照必须记录：

```yaml
data_snapshot:
  snapshot_id: ...
  source: ...
  variable_set: [...]
  observed_or_forecast: observation | forecast | reanalysis | derived
  valid_time_start: ...
  valid_time_end: ...
  issue_time: ...        # forecast 可填
  available_at: ...      # 必填或可由冻结规则确定
  retrieved_at: ...
  source_version: ...
  hash: ...
  forcing_mode_compatibility: [R, F]
```

核心判断不是：

> “这个文件是不是历史数据？”

而是：

> “在当前 `issue_time`，这个信息当时是否已经可以知道？”

## 8. B/F/E 阶段的数据权限

| 数据/行为 | B 构建 | F 回放 | E 评价 |
|---|---:|---:|---:|
| 训练/率定期 Q | ✅ | 只允许截至 issue_time 的状态输入 | 只读 |
| 测试期未来 Q | ❌ | ❌ | ✅ |
| R-mode future reanalysis | ✅，仅 R | R 任务可用；F 禁止 | 只读 |
| issue-time 合法天气 forecast | ✅ | ✅ | 只读 |
| 修改参数/权重 | ✅ | ❌ | ❌ |
| 根据测试 Q 改策略/Prompt/Gate | ❌ | ❌ | ❌ |

### 后端硬规则

```python
if phase == "F" and forcing_mode == "F":
    assert snapshot.available_at <= issue_time

if phase in {"F", "E"}:
    deny(calibrate_model)
    deny(adapt_model)

if phase != "E":
    deny(test_future_observation)
```

这些规则必须由执行器实现，不能只写在 Agent Prompt 中。

## 9. DataSnapshot 不允许静默覆盖

任何数据清洗、单位变换、PET 派生、时区/日界线修正都必须产生新快照：

```text
Raw Snapshot
     ↓
Transformation
     ↓
Derived Snapshot
```

必须记录：

- parent snapshot；
- transformation name/version；
- 输入/输出单位；
- 时间规则；
- 代码版本；
- hash；
- 产物引用。

Agent 和 Tool 只能引用 snapshot ID，不能直接修改原始文件。

## 10. 时间、日界线和单位规则

### 时间

必须明确区分：

```text
issue_time     起报时间
available_at   信息可获得时间
valid_time     数据代表的实际时间
target_time    预报目标时间
retrieved_at   本系统下载时间
```

USGS local day、UTC 气象数据和模型日尺度切片必须使用冻结转换规则。

### 单位

DataSnapshot 必须保留 source unit；模型 Adapter 显式转换为 model unit。

例如：

```text
streamflow: ft3/s → m3/s
precipitation: m → mm/day
radiation: J/m2 → model-required unit
```

不允许 Tool 根据字段名猜单位。

## 11. C0 实现顺序

不要一次把所有数据源接完。

### G0-A：先证明一个流域和一个模型真实跑通

优先尝试 OpenHydroNet，因为：

- `camels_13235000` 是官方教程示例；
- Caravan/MultiMet 与官方 loader 对齐；
- 可直接验证真实 lead 1/2/3 forecast。

完成：

```text
Basin
+ DataSnapshot
+ Model
+ Scheme
→ Forecast
```

### G0-B：XAJ R 模式

锁定具体 XAJ 实现、参数集、暖机规则、P/PET 语义和单位，然后完成一次 baseline + calibration。

### G0-C：严格 F replay

1. OHN：MultiMet HRES/GraphCast；
2. XAJ：后续接 GEFS Reforecast + forecast PET；
3. 冻结 issue-time 数据选择规则；
4. 再启动正式 historical replay。

## 12. 故障注入与 Agent 验证数据

Agent 能力不要求等待真实数据天然出现所有错误。正式定义一套可复现故障注入集：

| 故障 | 目标动作/结果 |
|---|---|
| 缺文件 | A01 检出 → A02 合法修复或 BLOCK |
| 单位错误 | A01 检出 → 转换形成新 snapshot |
| 重复日期 | A01 检出 → 可追溯修复 |
| 时区/日界线错位 | DATA/TIMING hypothesis |
| forcing 缺 lead | FORCING → BLOCK/换合法 forcing |
| candidate lead 3 明显退化 | Gate → ROLLBACK |
| 调参几乎不改变结果 | MODEL hypothesis weakened → KEEP/换检查 |
| F 阶段读取未来 observation | Permission Gate 拒绝 |
| F/E 调用 calibrate/adapt | Permission Gate 拒绝 |

故障注入必须从原始快照派生，不能污染 canonical dataset。

## 14. 首期完成门槛

数据部分算完成，当且仅当：

1. `camels_13235000` 的 basin metadata、Q 和至少一套真实 meteorological forcing 可读取；
2. 每个模型输入能追溯到 DataSnapshot；
3. 每个快照有 source/version/hash/time metadata；
4. R 与 F 在数据层可明确区分；
5. F 能拒绝 `available_at > issue_time` 的数据；
6. OHN 不使用 1982–2023 pretrained in-sample 指标作为独立测试结论；
7. XAJ 严格 F 模式不会偷看未来 ERA5 PET；
8. 数据错误修复会形成新 snapshot；
9. 至少一个模型真实产出 lead 1/2/3 Forecast；
10. 一条越权/泄漏数据读取被执行器真实拒绝并记账。

## 15. 数据层最终定位

本课题的数据层不是为了把公开数据“下载到本地”，而是为 Agent 提供一个**有时间语义、版本语义和权限语义的可审计水文世界状态**。

```text
Public Data
   ↓
Versioned DataSnapshot
   ↓
R/F Availability Rules
   ↓
HydroState / Forcing
   ↓
XAJ / OpenHydroNet
   ↓
Forecast
   ↓
Evidence
   ↓
Agent Decision
```

因此，数据可用性的核心标准不是“是否开源”，而是：

> **对于给定 issue_time，这条信息当时是否真实可获得、是否被允许进入当前阶段、是否能完整追溯。**
