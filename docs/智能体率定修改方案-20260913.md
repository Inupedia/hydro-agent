# 智能体率定修改方案：腰古与 Leaf River

审查日期：2026-09-13。代码基线：`46774b7`。状态：设计方案，尚未实施。

## 1. 范围与证据边界

本期仅覆盖产品目录中的 `yaogu`（腰古）与 `usgs_02472000`（Leaf River near Collins）。以当前真实工作台入口和本地资料为准。Lowman 历史实验不用于判断当前系统性能，也不作为本期验收对象。保留老师 XAJ 数值内核及其来源校验。

已检查真实入口、时窗、模型方案标准化、诊断、优化、Gate、回放、案例模块和 smoke 脚本。本轮选定测试集实际结果为 27 passed / 5 failed；未启动收费 LLM、重新率定两个流域或验证远程 CI，因此不对当前两个流域的实际 NSE 作结论。

本地腰古日资料文件覆盖 1989—2003 年，已检查首尾记录；Leaf River 清单记录 1979—2025 年、17,167 天，其中 2016-11-27 流量插补。上述覆盖信息不是完整数据质量审计，正式分割必须在逐日核验后锁定。

## 2. 当前问题与代码证据

| 问题 | 当前证据 | 影响 |
|---|---|---|
| 产品入口与科学家 smoke 不同 | `scripts/run_workbench_api.py:304,356` 使用 RealWorkbenchKernel 和 SiliconFlow；`scripts/smoke_yaogu_full_flow.py:218` 使用 CalibrationScientistWorkbenchKernel 和规则 provider | smoke 中的计划、失败反馈不能代表产品实际行为 |
| 两段时窗被当作独立检验 | `workbench/timeline.py` 默认末尾 30 天，最多 90 天；`workbench/real.py` 的 Gate、Replay 使用相同 runtime start/end | Gate 看过的数据不能再充当未参与选择的 final test |
| 长期率定与短期诊断口径不一致 | calibration_history_days 支持长序列；`data/windows.py` 的诊断默认只有 10 个起报日 | 多年参数选择可能被一个短期片段牵引 |
| 实验管理能力分散 | plan_from_diagnosis 由规则 provider 调用，reflect_on_gate 未接入执行主路径；案例写入见腰古 smoke | 结构化契约、日志、实际动作之间没有统一的执行权威 |
| 蒸发语义不同 | `modeling/plans.py:349` 明确腰古为实测蒸发，借用 pet_mm_day 字段；Leaf River 为 GridMET PET | 同名 K 的先验不能直接跨数据源使用 |
| 质量标记不贯穿评分 | Leaf River source-manifest 记录插补，FlowObservation 无 quality/scoring mask 字段 | 插补值可能作为真实观测参与优化和检验 |
| 搜索预算与维度不匹配 | 15 个参数；SCE-UA 默认 2 个 complexes，初始化 62 个点；全局策略预算 96 | 余下搜索有限，尚无依据声称充分收敛；500 上限也限制正式实验 |
| composite 定义过粗 | `models/xaj/calibrate_runtime.py:67` 使用全期最大峰、峰索引差除以全期长度、固定权重 | 多年峰时误差被稀释，不能代表多事件过程 |
| 搜索证据不充分 | 已有最优改善轨迹和边界命中；未见全 trial 账本、多 seed 研究与真实 XAJ 合成恢复基准 | 无法可靠区分搜索不足、参数不敏感和模型适用性问题 |
| Gate 混合“采用”与“合格” | `optimization/gate.py` 的 ACCEPT 分支不要求 min_primary_delta 达标 | 微小改善或容许范围内退化也可能被采用；低分但明显改善的候选又难以继续积累 |
| 回放反复重建状态与进程 | RealWorkbenchKernel 的逐日起报调用，以及固定历史长度 | 多年检验成本高，推动系统将检验压缩为 30 天 |
| 空间模型标签与实际率定表示可能不同 | 腰古标准化取首行参数、面平均强迫；US 方案将均匀强迫送入出口单序列 | 多单元计划必须明确实际执行表示，不能用集总率定证明分布式率定 |

五个本轮失败测试：test_gate.py 中两个旧 NSE fallback 断言；test_strategies.py 的旧 32 次预算断言；test_validation_binding.py 中诊断 fixture 缺前置强迫、bundle 仍按二元组解包。修复应落实新契约，不能恢复不合理 fallback 来求绿。

## 3. 目标执行结构

统一装配入口：已复核模型方案 → 数据与分割协议 → 连续基线模拟 → 诊断证据 → Agent 提议实验 → 确定性计划校验 → 数值搜索 → development 比较 → 采用/拒绝与反思 → 下一实验或冻结 → final test → 报告。

真实 LLM、规则基线、固定优化器基线共享同一数据、模拟器、指标、预算计数和实验账本。差异仅为由谁提出下一实验。首期不增加流域、不训练领域 LLM、不引入多 Agent、不替换老师内核。

### 3.1 统一协议对象

新增版本化 CalibrationProtocol，包含 basin_id、model_plan_id/hash、实际模型表示、forcing/evaporation 语义、source/quality mask hash、warmup/calibration/development/final_test、指标与 Gate 版本、预算与 seed 列表、provider 版本。

新增 ExperimentPlan，包含 experiment_id、parent_experiment_id、hypothesis、evidence_refs、可证伪预期、参数组/冻结组、objective_id、optimizer_id、local/global scope、边界版本、seed、评估预算、停止规则。LLM 只能选择注册的选项或解释建议，连续参数由数值优化器生成。

计划校验器返回 validated_plan 或明确拒绝原因，并记录 proposed_decision、executed_decision 和 override_reason。禁止日志呈现的计划与实际执行不一致。

新增 ExperimentResult，保存参数变化、cal/development 分量指标、有效样本数、调用次数、有效/无效/重复 trial、费用、运行时间、Top-K、边界命中、收敛状态、采用判定与资格判定。所有 evidence 引用绑定同一个 experiment_id。

## 4. 分期修改内容

### P0：统一实际入口和契约

- 从 run_workbench_api.py 抽出共享 runtime factory；真实 API、CLI 和 smoke 均调用。将结构化计划与失败反馈提升到服务层，不靠换 provider 才启用。
- 替换 SiliconFlow 的固定策略轮换为经过校验的实验提议；保留权限、故障恢复与收尾约束。规则 provider 调同一计划服务，作为可复现基线。
- Gate bundles 用命名模型取代二元/三元 tuple；缺标准报告保留明确的不可资格认证状态。
- 修复现有五个回归测试，并增加同一任务配置通过 API 与 smoke 获得相同 snapshot/plan/Gate 输入的集成测试。
- 创建任务前完成时窗与成本校验，或使用事务，避免当前 create_task 后校验失败留下残缺任务。

涉及：scripts/run_workbench_api.py、api/services.py、agent/providers/*、workbench/real.py、workbench/calibration_scientist.py、optimization/calibration_scientist.py、对应 tests。

验收：两流域入口装配一致；拟议与执行动作可追踪；回归全绿；实际 LLM 失败必须显式标明 fallback，不得冒充 LLM 决策。

### P1：明确数据语义及三段窗口

- 正式率定使用显式 calibration、development、final_test；warmup 独立标记。原 validation_days 保留给快速演示模式，不能生成“独立最终检验”结论。
- calibration 观测供数值搜索和诊断；development 供有限次数的实验选择；final_test 观测不进入 Agent、先验、案例检索或选择过程。
- 分割按目标日期定义。保留 lead 回放时对边界加 gap 或裁剪，防止 development 最后三个起报日读取 final_test 观测。
- A10 冻结参数、策略、协议和数据哈希；A11/A12 使用 final_test。确定性重算允许，但读取最终检验后的调参必须开启新实验版本，并标记旧 test 已使用。
- FlowObservation 增加 quality、imputation_method、eligible_for_scoring；snapshot/export/evaluation 保留同一 mask。2016-11-27 不参与正式观测评分，单独给出包含插补值的敏感性结果。
- 记录腰古实测蒸发与 Leaf River PET 的语义，先验匹配必须包含 forcing_semantics。保留老师原转换，检查 K 的实际作用再定边界。
- 审核腰古 08:00 日标签和 Leaf River 源日界，使用固定数据协议，不能为改善 NSE 选择日期平移。
- 实际执行模式写入 execution_representation。本期验收集总路径；多单元模式若未验证，应阻止其以“分布式率定”名义运行。

涉及：data/contracts.py、data/snapshot.py、services/snapshots.py、modeling/plans.py、modeling/us_plans.py、workbench/timeline.py、api/schemas.py、api/services.py、replay/*。

验收：修改 final_test 流量不会改变最终检验前的 Agent 决策与候选参数；cal/development/final_test 的样本掩码与日期数可独立重算；短期资料仅报告流程可运行。

### P2：连续模拟与全窗口诊断

- 新增 ContinuousSimulationService：一次加载强迫与初始化，在同一连续轨迹上输出 baseline/candidate 日流量、状态和全期指标；按显式窗口评分。
- 优化器、诊断和 Gate 使用相同连续模拟口径，warmup 不参与评分。development 和 final_test 状态由历史强迫连续推进，不读取未来观测初始化。
- 10 日诊断保留为 recent diagnostic，正式计划同时收到全率定期、逐年、季节、低流量、洪峰事件和退水证据。
- 事件检测规则在协议中预先锁定；相邻峰需合并和独立性约束，峰时按天计算，不除以多年长度。日模型只评价日尺度峰时，腰古小时次洪资料另建后续协议。
- 计算缓存键包含模型/方案/数据/初始化/窗口/质量掩码版本。预算统计区分 cache hit、逻辑评估次数与真实模型执行。
- R 模式历史回算优先连续模拟；若保留 lead 回放，先证明与参考逐日起报状态语义一致再加速。F 模式不得复用事后强迫宣称业务预报能力。

涉及：新增 services/continuous_simulation.py；models/xaj/upstream.py 只作适配调用；services/calibration_diagnostics.py、workbench/validation_gate.py、evaluation/hydrograph.py、replay/service.py。

验收：连续/分块恢复/参考老师输出一致；诊断与 Gate 的同一指标重算一致；多年资料不再被费用护栏自动压成一个月；计时后再确定正式预算。

### P3：数值优化与实验账本

- 引入优化器接口，实现 SPOTPY SCE-UA 参照适配器与 DDS；保留当前自写 SCE-UA 作对照。版本锁定，统一目标方向、参数边界、非法候选和预算口径。
- 基于两个流域的真实强迫构造已知参数的合成观测。先无噪声、后加可控噪声；优先测试输出恢复与敏感参数恢复，不要求不可辨识参数精确等于唯一真值。
- 在 calibration 上做参数敏感性与组内相互影响分析。单参数扫描用于排错，Morris 等筛选用于决定维度；不凭经验固定所有流域都只开放相同 6 个参数。
- 允许科学家选择预注册的预算档位。建议先测 256/1024/4096 的收敛曲线；正式同预算比较初始设 4096 次/seed，3 个 seeds，在运行成本与收敛证据不足时调整。数值只是本项目试验设计，不是论文规定。
- 每次 trial 持久化参数、完整分量得分、来源 seed、有效性/拒绝原因、时间、当前最优。跨实验缓存避免固定 seed 和未变基线重复跑同一搜索。
- 将数值预算从 max_candidates 和 Agent action rounds 中拆出：task_total_evaluations、per_experiment_evaluations、wall_time、LLM calls、实验次数。
- 记录停止原因：converged、budget_exhausted、no_improvement、infeasible、execution_failed。预算用尽不能写成收敛，微小参数变化不能写成率定成功。
- 增加优化器断点恢复；大预算任务异步执行，保留心跳、取消与资源界限。按实测成本调整当前 600 秒执行时限，不能直接取消时限。

涉及：optimization/contracts.py、strategies.py、sceua.py、新增 optimizer adapters/sensitivity；models/xaj/calibrate_runtime.py、services/calibration.py、execution/runner.py、persistence/*。

验收：相同配置与 seed 可复现；硬预算无越界；非法/重复候选单列；任务可恢复；自写 SCE-UA 与参照在合成/真实任务上具备可比较的收敛证据。

### P4：指标、采用规则与成功语义

- 第一版以 NSE 为固定主指标，KGE 分量、PBIAS、低流量与事件指标作为显式护栏；随后增加预注册的多目标 profile。避免一次改很多权重而无法归因。
- 替换全期单个最大峰的 composite；保存每个分量及其量纲、归一化方式。相同指标的定义在诊断、优化、Gate 和报告中一致。
- 保留 Top-K/非支配候选用于诊断；选择规则在运行前固定。不要把多 seed 的离散程度直接称为概率置信区间。
- Gate 分成 adoption 与 qualification。adoption 决定是否替换当前工作方案，qualification 决定是否具备预设精度资格。通过指标改善护栏但未合格的候选可作为下一轮工作基线，不能对外发布为合格方案。
- adoption 明确要求 improvement_threshold（按预注册规则）及非退化护栏；同参数或无有效改善不能仅因达到绝对分数而重复 ACCEPT。
- 标准评价样本不足返回 insufficient_evidence，技术故障返回 evaluation_failed；不得把缺报告硬解释为水文机制失败并继续乱搜。
- 报告分别显示 execution_completed、candidate_adopted、development_qualified、final_test_passed。冻结失败基线是合法收尾，但须显示未取得合格改进。
- Baseline 同时报未率定方案和同预算固定优化器；persistence 仅用于对应起报实验，其信息可用性需与模型一致。连续模拟不混入不同信息条件的预报比较。

涉及：evaluation/metrics.py、evaluation/hydrograph.py、optimization/gate.py、optimization/contracts.py、agent/tools.py、replay/freeze.py、reporting/report.py。

验收：负分但显著改善、已合格但退化、无参数变化、缺标准报告、缺观测五类都有明确预期；模型同数据同参数的报表可复核。

### P5：接通科学家决策和案例反馈

- WorldState 提供全期诊断摘要、分组敏感性、搜索覆盖与边界命中、cal/development 分量、Top-K、已失败假设、剩余预算和可用证据引用。
- Agent 明确提出“什么现象、什么假设、什么实验、预期哪项指标怎样变、何时判假”。禁止用固定 0.95 strength 冒充实证置信度。
- 反思按实验结果决定：维持假设扩大覆盖、更换参数组、增加预算、缩小范围、转数据检查、请求能力补充或终止。一次 Gate 失败只能反驳本次实验，不自动证明整个参数组或模型结构无效。
- 触及局部边界可在绝对边界内扩展；触及绝对边界返回证据，不自动改变老师内核约束。
- 结构性不匹配只作为需验证的假设。本期围绕腰古和 Leaf River 的实测误差提出具体原因，不预设 Lowman 的融雪解释。
- 将案例写入从 smoke 移到 Resolve 之后的幂等服务。案例包含协议/模型/强迫/质量/指标版本和使用窗口，只存经过审计的结果。
- 检索按上述兼容条件过滤，再按现象和参数组匹配；不把当前或其他实验 final_test 的结果泄漏到本次选择。腰古与 PET 案例不直接共享 K 数值先验。

涉及：agent/world_state.py、agent/contracts.py、agent/providers/*、optimization/calibration_scientist.py、knowledge/cases.py、knowledge/expert.py、agent/tools.py。

验收：相同失败证据不无限重跑同一实验；新的边界/敏感性证据可以改变合法计划；修改不相关案例不影响决策权限；实际 API 记录计划、执行、反思及案例引用。

### P6：结果展示、兼容与验收

- 在现有结果页增加 calibration/development/final_test 切换，显示该窗口是否参与选择、样本数、插补排除数、baseline/candidate/frozen 与完整过程线。
- 执行日志展示本轮假设、实验设置、实际成本、结果和下一步原因。已有日志布局保留，增加必要字段即可。

- 实验记录先落不可变产物，DB 保存索引/状态；接受候选和状态更新事务化，重试以 experiment_id 幂等。
- 快速 CI 测契约、窗口隔离、状态连续、预算和模拟小样本；真实两个流域验收由独立慢任务产生产物。不能以 deterministic smoke 替代真实 LLM 验收。

## 5. 两流域实验协议建议

以下日期是根据当前资料覆盖提出的默认方案，须在运行前通过覆盖、预热与质量检查锁定；不依据最终分数改日期。若已有这些年份的结果被用于策略开发，需标记暴露并另行设计最终检验。

| 流域 | warmup | calibration | development | final_test | 专项检查 |
|---|---|---|---|---|---|
| 腰古 | 1989 | 1990—1997 | 1998—2000 | 2001—2003 | 实测蒸发、08:00 日界、面雨量及老师参数映射 |
| Leaf River | 1979 | 1980—2004 | 2005—2014 | 2015—2025 | GridMET 强迫聚合、PET、USGS 质量与 2016-11-27 插补掩码 |

每个流域分别比较：初始方案；O 固定数值优化；P 规则科学家；A 真实 LLM 科学家。O/P/A 使用相同总数值预算、数据/边界、候选合法性和最终采用规则；超参在 development 中固定。固定策略的不同优化器先做预实验，再确定 O 基线，不能只选弱对手。

每组初始 3 个 seeds，共 2 × 3 × 3 = 18 个正式策略运行（不含初始方案和前置优化器对照）；若每运行 4096 次，则为 73,728 次评估上限。先计时和确认可承受成本，不预先承诺完成时长。所有不成功运行计入统计，不只展示最好一次。

正式报告包括每流域各 seed 的 cal/development/final_test 多指标、配对差值、模型执行次数、LLM 时间/费用、运行失败、停止原因、参数分布与事件诊断。只有两个流域时只作两个案例的有效性结论，不能宣称广泛跨流域泛化。

Agent 价值判据在预实验后、正式测试前锁定：相同预算下的精度和稳定性，或达到同等预注册精度所需成本。若 A 未优于 O/P，应如实报告并让产品提供固定优化或规则模式，不能借解释文字掩盖无增益。

## 6. 推荐实施顺序与交付边界

| 批次 | 交付 | 前置依赖 | 必须通过 |
|---|---|---|---|
| 1 | P0 统一入口、命名契约、回归修复 | 当前代码 | 测试通过、API 与脚本配置一致 |
| 2 | P1 数据协议、质量掩码、三段时窗、迁移 | 批次 1 | 日期泄漏与旧任务兼容测试 |
| 3 | P2 连续模拟、状态恢复、全窗口诊断 | 批次 2 | 老师输出等价与完整窗口计数 |
| 4 | P3 数值适配、敏感性、预算、trial 账本 | 批次 3 | 合成恢复、可复现、断点恢复 |
| 5 | P4 Gate 与指标，P5 实验反思 | 批次 3、4 | 采用/合格分离、失败原因驱动决策 |
| 6 | P6 页面、真实两流域 O/P/A 验收 | 批次 1—5 | API 真实路径及独立报告、浏览器验证 |

分批提交的测试门槛包括相关 pytest、全仓回归、Ruff、workflow 同步检查、前端类型与构建检查。最终验收由实际 API 创建两个流域任务、记录真实 provider 请求、完成优化/选择/冻结/最终检验，核对产物和 UI；每一项失败都保留错误、可恢复点及未完成项。

## 7. 论文与开源参照的采用方式

- [SPOTPY 官方 SCE-UA 示例](https://spotpy.readthedocs.io/en/latest/Calibration_with_SCE-UA/)：用作优化器适配和轨迹保存参照。示例 5000 次并不代表对本项目保证收敛，预算由本项目维度与收敛试验决定。
- [Zhu et al., 2026, GRL](https://agupubs.onlinelibrary.wiley.com/doi/10.1029/2025GL120043)：借鉴 LLM 与传统优化器对照及成本报告；不照搬直接生成参数的职责设计，也不把其流域结果当成本项目验收阈值。
- [HydroAgent 开源项目](https://github.com/zhuanglaihong/HydroAgent)：借鉴外层调搜索范围、内层数值优化的结构；与 simulator-grounded RL 同名论文不能未经核验视为同一项目。其示范分数不证明本项目效果。

本期成果应是两个现有流域上可复现、可解释失败、真正执行统一科学实验协议的率定闭环。是否提高最终精度，由正式实验回答。
