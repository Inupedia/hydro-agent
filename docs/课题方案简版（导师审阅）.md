# 基于智能体的水文预报方案构建及参数优化
## 课题方案简版（供导师审阅）

**面向：** 河海大学数字孪生卓工班（二期）

**指导教师：** 方园皓 副教授

**修订日期：** 2026 年 9 月 7 日

**状态：** 设计阶段，模型可行性与效果待实测。

## 一、课题要解决的问题

水文预报人员的工作包括检查资料、建立预报方案、准备起报条件、运行模型、分析偏差、选择处理措施、重算验证和复盘。本课题拟以 Google OpenHydroNet 为模型基础，让 Agent 在限定范围内自主承担这些工作。

系统配置一次任务后自动运行，无需人员逐轮输入“分析原因”“调整参数”。Agent 根据资料、计算结果和历史记录决定下一步；资料与方案正常时直接预报，出现问题时排查并选择有依据的处理措施。

**研究重点是 Agent 能否自主完成预报工作、合理选择处理动作并验证效果。参数优化是其中一种措施，不要求每次预测都重新调参。**

## 二、输入、输出与研究范围

输入为公开流域资料、历史气象、起报时刻可获得的未来气象预报，以及模型和运行预算。优先从官方示例覆盖的美国或欧洲流域中选一个资料完整、计算成本可控的对象。

核心输出为目标站点未来第 1、2、3 日的流量预测，同时保存所用方案、资料质量、处理过程和事后评价。站点流量预测不直接等同于洪水淹没范围预测。

本期采用单流域、日尺度历史回测，使用一台 M1 Pro 和第三方大模型 API；不开展实时防汛应用、闸门控制、全球模型训练或三维淹没仿真。

## 三、Agent 具体做什么

| 遇到的情况 | 判断与处理 | 如何验证 |
|---|---|---|
| 初次运行，没有适用方案 | 检查资料与模型能力，组装并试运行预报方案 | 输入匹配、真实输出可复现 |
| 资料缺失、单位或时间异常 | 根据来源排查，补取或纠正确证错误 | 来源与处理记录可追溯 |
| 起报历史窗口或缓存不匹配 | 使用合法历史资料重新建立计算条件 | 时间边界正确、重复计算一致 |
| 洪峰、总体水量或峰现时间偏差 | 区分资料、起报与模型问题，形成待验证假设 | 多事件指标与资料证据共同支持 |
| 有依据开展模型适配 | 选择允许的微调配置，调用训练程序重算 | 比较目标误差及其他指标，保留或撤销 |
| 方案正常、调整无效或能力不足 | 直接预报、维持当前方案或明确收尾 | 不盲目干预，所有失败有结论 |

新安江模型中可解释的蓄水、汇流参数，不能直接套到 LSTM。OpenHydroNet 的微调模块、学习率和训练长度只是适配手段；隐藏状态存取也不等于已经支持实测流量同化。具体可用动作将依据代码和小规模实验确认，不预先承诺所有误差都能自动修复。

## 四、自主运行与验证方式

**检查资料 → 建立方案 → 在历史开发资料上运行 → 判断问题并选择动作 → 执行与验证 → 冻结方案 → 自动逐日起报 → 独立评价与结论。**

准备与改进阶段可使用训练、验证资料；独立回测阶段只按冻结规则和当时可得信息预报；最后统一读取测试真值评价，不能利用测试结果继续本轮调参。

同时核查预训练权重的历史覆盖，避免测试时期已经进入基础模型训练。若只能取得未来实测或再分析气象，结果明确称为“理想气象驱动回算”，不冒充真实提前预报能力。

实验分两部分：一是与固定业务流程比较问题发现、动作选择、任务完成和干预成本；二是在同一数据与预算下，与基础模型、固定微调、规则策略及 Optuna 比较预测效果。这样既评价预测精度，也检验 Agent 实际接过了哪些人员工作。

允许未提升、退化和受阻结果，但必须说明观察事实、可能原因、证据限制和后续验证方向，不预先承诺优于传统优化。

## 五、技术实现与拟交付成果

先确定“问题—证据—处理动作—验证”契约，再据此划分体系内 Agent Skills。Skills 封装可复用工作方法、工具和验证要求；LangGraph 负责自主循环、等待和恢复；LangChain 对接第三方 API；OpenHydroNet 承担计算。本阶段仅设计，不编写 Skill 文件或实现代码。

首先在 M1 Pro 上完成一次推理和小规模微调，检查资料合法性、内存与耗时，再决定预算和具体技能边界。

拟交付可操作网页、可执行预报方案、预测及完整动作记录、对照实验结论，以及答辩 PPT 与图表素材。网页重点展示“Agent 发现什么、为什么这样处理、处理后怎样”，支持预报回放和方案比较，二维地图用于说明流域位置。
