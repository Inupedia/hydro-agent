# 基于智能体的水文预报方案构建及参数优化
## 课题方案简版（导师审阅）

**面向：** 河海大学数字孪生卓工班（二期）

**指导教师：** 方园皓，河海大学水文水资源学院副教授

**日期：** 2026 年 9 月 7 日

**状态：** 设计阶段，数据、模型与减负效果待实测。

## 一、课题要解决的问题

水文模型使用人员需要反复核查资料、准备配置、运行预报、排查偏差、尝试适配、比较结果和整理报告。本课题拟构建能够自主承担这些操作与判断的智能体，减少逐轮指挥、重复检查和异常返工。

**核心问题是在相同数据、工具和资源约束下，智能体能否以合格的预报质量与任务完成率，降低人员主动工时。** 系统读取一次配置的任务后自动执行，正常时直接预报，有问题时依据证据选择处理措施，无法处理时保存现场并说明原因。

已有文献已探索水文 Agent 率定、全流程建模和 Skills 化预报经验。本课题将重点放在业务动作的可靠执行及人工减负验证，不将使用框架或自动调参本身作为首创。[Skills 预报研究，预印本](https://arxiv.org/abs/2607.23983)；[LLM 率定研究，GRL](https://doi.org/10.1029/2025GL120043)。

## 二、模型、数据与研究范围

优先采用 Google OpenHydroNet 的轻量模型，在一台 M1 Pro 上完成单流域推理和有限局部适配，LLM 使用第三方 API。首选核查官方教程流域 `camels_13235000`，即美国 South Fork Payette River at Lowman；是否采用取决于资料、训练来源和本机实测。

输入包括模型要求的历史气象、未来气象驱动、流域属性与方案；实测流量用于合法训练、历史诊断和事后评价。输出为站点未来第 1、2、3 日流量、资料质量、处理记录和结果报告。

采用日尺度历史起报回放，不开展三维淹没仿真或实时防汛应用。使用起报时可得历史气象预报的实验，评价提前预报；如只能取得未来实测或再分析气象，则明确为理想气象驱动回算。

公开预训练权重存在历史训练覆盖问题，须先核查权重与数据切分；教程可运行不等于已经具备合法独立测试。[OpenHydroNet 官方仓库](https://github.com/google-research/flood-forecasting)。

## 三、智能体实际承担的工作

| 人员工作 | 智能体的处理 | 验证方式 |
|---|---|---|
| 查资料和异常来源 | 组织证据，补取或纠正确证错误 | 来源、单位、时间与修改差异可核对 |
| 配置模型与准备历史条件 | 选择兼容模板，校验并重建计算窗口 | 真实输出、版本一致、时间合法 |
| 构建水文上下文 | 读取程序生成的当前流量、前期降水、未来 forcing、季节与历史相似过程 | 所有字段可追溯到数据快照和确定性计算 |
| 排查预报偏差 | 在 DATA/TIMING/STATE/FORCING/MODEL/UNKNOWN 原因空间内形成候选解释 | 多证据、相似历史过程及替代解释支持 |
| 决定是否适配 | 有依据时选择已验证的局部适配策略，并委托优化器执行候选 | 统一验证，合格才采用，否则撤销 |
| 连续起报与失败处理 | 自动推进任务，有限恢复或明确受阻 | 完成状态、接管和费用全部记录 |
| 复核与报告 | 汇总结果、失败结论与图表 | 数字来自真实产物，人工复核计入成本 |

不把“洪峰偏低”直接解释为应调整某个学习率，也不把单次误差默认归因于模型。Agent 先检查资料、时间、历史状态和未来气象驱动不确定性，再判断是否存在持续模型偏差。

本课题增加确定性的 **Hydrologic Context Builder**，程序生成当前流量分位数、前 3/7/14 日降水、未来三日 forcing、HRES/GraphCast 分歧、季节/雪背景、近期模型表现和 Top-K 历史相似过程；Agent 只读取证据并选择下一动作，不自己计算水文量。

参数优化采用“**Agent 选策略、Optimizer 选数值**”的分工。正式实验前先做小型机制实验，比较 `head`、`static_embedding_fc`、`static_embedding_fc + head` 等局部适配方式的有效性和本机成本，再冻结正式允许策略。Agent 不直接修改神经网络权重或连续超参数。

## 四、自主运行与 Skills 设计

采用一个主 Agent。LangGraph 管理“观察证据—选择动作—调用工具—验证—继续或结束”的循环，LangChain 接入 API。五类业务包暂为资料核查、方案执行、预报诊断、有限适配、评价报告；Skills 从动作案例提炼处理方法、工具和验收要求，本阶段不编写实际 Skill 文件。

运行分三段：**历史资料上的方案构建与适配 → 冻结方案后的逐日起报 → 独立只读评价。** 起报时不读取未来流量真值；独立测试不反向调参。资料正常、forcing 不确定或调整无效时允许维持方案，不要求每轮都优化。

预报诊断 Skill 要求优先检查 DATA、TIMING、STATE 和 FORCING，再提高 MODEL 假设优先级；证据不足时允许 UNKNOWN/BLOCK。相似历史过程仅从开发期合法资料检索，不能从独立测试集形成“经验”。

## 五、如何证明减少人工

设置三个主组：H 为人员使用共同工具；P 为固定自动化流程；A 为业务动作 Agent。资源允许时增加通用 Agent 消融组。三组使用相同数据、模型起点、Hydrologic Context、工具、优化空间和计算预算。

计划 15 个正式任务包，覆盖正常、资料异常、运行异常、模型偏差和证据不足。任务中至少覆盖：forcing 分歧高且不应调参、持续模型偏差可考虑适配、适配后某 lead 退化应撤销、历史相似过程不足应保留 UNKNOWN/BLOCK、正常高流量不应误干预。开发案例与正式任务分开，真实问题与注入故障分别报告。

主指标是人员主动工时，包含准备、核查、接管、纠错和最终复核；计算等待另计。同时评价预报质量、合格完成率、错误干预、无效试验、**不必要模型适配率、forcing 问题误判为 model bias 的比例**和 API 费用。失败任务保留，不能只统计成功案例的节省比例。

候选模型采用分层质量门槛：先检查产物合法性和覆盖率，再检查各 lead 是否不可接受退化，再检查高流量/事件指标，最后才比较总体 NSE/KGE。平均分提升不能掩盖关键 lead 或洪水事件表现明显变差。

15 个任务用于探索性工程验证，不预先承诺统计显著。若参与者只有学生，结论限定为学生或模型使用者的操作负担；专业人员减负需另有专业人员对照。

## 六、实施与交付

依次完成模型与数据门槛、共同工具、**水文上下文与历史相似过程工具、局部适配机制实验**、固定 Pipeline 与先导任务、主 Agent、实验冻结、H/P/A 比较及网页答辩。先验证一次真实推理和微调，再扩大开发。

交付预报工作台、可复现方案与预测、完整动作和成本账本、对照结论、结题报告及答辩 PPT。网页突出过程线、水文上下文、forcing 分歧、相似历史过程、处理证据、方案采用/撤销和工时对比。未提升或 Agent 不如固定流程同样如实报告，但不代替完整实验。

希望导师重点指导：业务原因空间是否合理；水文上下文字段及历史相似过程是否符合实际预报判断；质量容忍门槛如何设定；能否核对少量典型处理案例并确定真人实验对象。
