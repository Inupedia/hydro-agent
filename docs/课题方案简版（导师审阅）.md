# 基于智能体的水文预报方案构建及参数优化
## 课题方案简版（供导师审阅）

**适用：** 河海大学数字孪生卓工班（二期）  
**指导教师：** 方园皓 副教授  
**方案状态：** 拟实施，模型效果与本机计算成本待验证。

## 一、研究目标

基于 Google 开源水文预测框架 OpenHydroNet，选择一个具有公开数据的美国或欧洲流域，开发由智能体辅助构建预报方案、优化模型参数并解释实验结果的网页系统。

重点研究：**智能体能否根据数据条件和模型表现，组织有效的模型配置与参数优化过程，并给出有证据支持的推荐方案。** 项目采用日尺度历史回测，首先关注未来 1—3 日流量预测，不涉及实时防汛应用和洪水淹没计算。

## 二、拟采用的技术路线

**公开数据 → OpenHydroNet 基础模型 → 智能体生成方案 → 执行微调与评价 → 比较并推荐方案 → 网页展示与答辩报告。**

优先复用 OpenHydroNet 官方教程的模型、数据接口和训练流程，不自行重写水文模型。先复现小规模示例，再选定一个数据完整、计算成本可控的目标流域。原方案中的 Fish River 不作为固定研究对象。

本期“方案构建”限定为：智能体在经过验证的模型模板内，配置数据、预见期、微调策略和运行预算，生成能够保存、执行和复现的预报方案。暂不开展任意模型自动生成或多模型平台建设。

本期“参数优化”主要指神经网络模型的微调与超参数选择，包括学习率、训练轮数及允许更新的网络模块，**不将其表述为传统水文模型物理参数率定**。智能体选择配置、提出假设和调用工具，模型权重由训练算法更新。

## 三、智能体编排与工作内容

拟采用 **LangGraph + LangChain 模型组件** 实现智能体：LangGraph 编排方案构建、诊断、调参、评价及循环；LangChain 连接第三方大模型 API，提供结构化决策；OpenHydroNet 承担实际训练与预测。

编排流程为：

```text
检查数据 → 智能体构建方案 → 程序校验
                             ↓
诊断并提出参数 → 校验并提交训练 → 等待任务完成
      ↑                              ↓
继续优化 ← 保存实验记录 ← 程序评价并保留/拒绝
                             ↓ 达到停止条件
                       冻结推荐方案
```

这是一套有状态的单智能体流程。LangGraph 保存当前阶段、候选参数和结果引用，支持长任务等待、暂停与恢复；训练任务由独立进程执行。程序控制预算和接受规则，最终测试在搜索结束后独立进行。网页同步展示节点进度、调参依据和成功或失败路径，答辩可展示真实编排轨迹。

| 工作 | 具体产出 |
|---|---|
| 检查数据并配置方案 | 数据条件说明、模型配置与可执行方案 |
| 诊断预测表现 | 总体偏差、不同预见期及高流量事件的误差摘要 |
| 提出并执行调参试验 | 有依据的候选配置、训练记录和预测结果 |
| 比较并推荐结果 | 保留或拒绝的理由、推荐方案及适用限制 |

智能体通过第三方大模型 API 运行。程序限制可调整参数、试验预算和评价规则，保留全部成功、退化与失败记录。智能体不能修改观测数据、评价标准或依据测试结果继续调参。

## 四、实验验证与结论

设置基础模型、固定微调配置、固定规则优化、Optuna 优化与智能体优化等对照；条件允许时增加简单流量持续性基线。

各优化方法使用相同基础模型、数据划分、参数范围和试验预算，分别评价 1、2、3 日预测的 NSE、KGE、流量误差及高流量事件表现，同时记录训练时间、大模型调用成本和运行失败情况。资源允许时开展重复实验，判断结果是否稳定。

**训练集用于模型学习，验证集用于选择参数，测试集仅用于方案冻结后的最终评价。** 还需检查基础模型是否已经训练过拟测试年份，避免仅重新划分本地数据却仍存在预训练信息泄漏。

历史回测优先采用起报时刻可获得的气象预报资料。如果只能取得未来实测或再分析气象，则明确定位为“理想气象驱动回算”，不以其成绩证明实际提前预报能力。

不预先承诺智能体优于 Optuna。若没有提升，仍须回答：在什么条件和预算下未获益、哪些指标或事件发生退化、可能原因有哪些、还缺少什么验证。运行失败与效果不佳分别记录，不能用推测代替结论。

## 五、实施条件与成果形式

计算使用现有 M1 Pro，第三方 API 承担大模型推理。本地优先运行官方小模型及有限模块微调，串行开展少量参数试验，避免全球模型训练和大范围搜索。

首先完成数据读取、一次推理、一次小规模微调，并实测内存与耗时。基础权重若不满足独立测试要求，再评估基于官方架构训练一次轻量基础模型的成本。**能否在本机完成合法、可复现的回测，是进入完整开发的首个门槛。**

拟交付：

- **网页系统：** 数据与流域、方案构建、优化过程、结果与结论四个页面。
- **实验成果：** 可执行配置、预测结果、对照指标、完整试验记录和成功或失败结论。
- **答辩材料：** PPT、讲解提纲及可导出的图表，包括流程图、流域图、预测过程线、优化轨迹和效果—成本对比。

可视化以二维流域地图和时间序列图表为主，支持按起报日回放预测过程。三维展示不列为必做，不制作缺少模型依据的洪水淹没动画。

## 六、实施顺序与请导师指导的事项

实施顺序为：**官方示例复现与数据核查 → 冻结回测方案 → 跑通模型及常规优化 → 接入智能体 → 完成网页与正式对照 → 整理答辩材料。**

该路线尽量利用已有模型，把新增工作集中在方案组织、受控调参和实验解释上，具有开展小规模验证的基础；具体预测效果和计算可行性仍需首阶段实测。若 Google 路线确实无法满足条件，再就新安江备选方案另行讨论，不在本期同时铺开两条路线。

希望导师重点指导：

1. 将“方案构建”限定为官方模型模板内的可执行配置，是否符合课题要求？
2. 以有限模块微调和超参数优化作为主要研究内容，是否合适？
3. 采用单流域、日尺度历史回测，并以对照实验及过程可解释性作为主要成果，研究范围是否适当？
