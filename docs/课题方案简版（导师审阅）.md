# 基于智能体的水文预报方案构建及参数优化
## 课题方案简版（导师审阅）

**面向：** 河海大学数字孪生卓工班（二期）

**指导教师：** 方园皓，河海大学水文水资源学院副教授

**日期：** 2026 年 9 月 7 日

**状态：** 设计阶段，数据、模型与减负效果待实测。

## 一、课题要解决的问题

水文模型使用人员需要反复核查资料、准备配置、运行预报、排查偏差、尝试适配、比较结果和整理报告。本课题拟构建能够自主承担这些操作与判断的智能体，减少逐轮指挥、重复检查和异常返工。

**核心问题是在相同数据、工具和资源约束下，智能体能否以合格的预报质量与任务完成率，降低人员主动工时。** 系统读取一次配置的任务后自动执行，正常时直接预报，有问题时依据证据选择处理措施，无法处理时保存现场并说明原因。

已有文献已探索水文 Agent 率定、全流程建模和 Skills 化预报经验。本课题将重点放在业务动作的可靠执行及人工减负验证，不将使用框架或自动调参本身作为首创。[Skills 预报研究，预印本](https://arxiv.org/abs/2607.23983)；[LLM 率定研究，GRL](https://doi.org/10.1029/2025GL120043)。

## 二、模型、数据与研究范围

优先采用 Google OpenHydroNet 的轻量模型，在一台 M1 Pro 上完成单流域推理和有限局部适配，LLM 使用第三方 API。首选核查官方教程流域 `camels_13235000`，即美国 South Fork Payette River at Lowman；是否采用取决于资料、训练来源和本机实测。

输入包括模型要求的历史气象、未来气象驱动、流域属性与方案；实测流量用于合法训练、历史诊断和事后评价。输出为站点未来第 1、2、3 日流量、资料质量、处理记录和结果报告。

采用日尺度历史起报回放，不开展三维淹没仿真或实时防汛应用。使用起报时可得历史气象预报的实验，评价提前预报；如只能取得未来实测或再分析气象，则明确为理想气象驱动回算。

公开预训练权重存在历史训练覆盖问题，须先核查权重与数据切分；教程可运行不等于已经具备合法独立测试。[OpenHydroNet 官方仓库](https://github.com/google-research/flood-forecasting)。

## 三、智能体实际承担的工作

| 人员工作 | 智能体的处理 | 验证方式 |
|---|---|---|
| 查资料和异常来源 | 组织证据，补取或纠正确证错误 | 来源、单位、时间与修改差异可核对 |
| 配置模型与准备历史条件 | 选择兼容模板，校验并重建计算窗口 | 真实输出、版本一致、时间合法 |
| 排查预报偏差 | 区分资料、计算条件和模型问题，保留替代解释 | 历史指标及多事件证据支持 |
| 决定是否适配 | 有依据时委托优化器执行有限候选 | 统一验证，合格才采用，否则撤销 |
| 连续起报与失败处理 | 自动推进任务，有限恢复或明确受阻 | 完成状态、接管和费用全部记录 |
| 复核与报告 | 汇总结果、失败结论与图表 | 数字来自真实产物，人工复核计入成本 |

不把“洪峰偏低”直接解释为应调整某个学习率。Agent 决定是否适配及采用哪类策略，优化器搜索数值，模型负责流量计算，程序负责评分和回退。首期拟仅微调实际模块 `static_embedding_fc`，预算经本机实测后冻结。

## 四、自主运行与 Skills 设计

采用一个主 Agent。LangGraph 管理“观察证据—选择动作—调用工具—验证—继续或结束”的循环，LangChain 接入 API。五类业务包暂为资料核查、方案执行、预报诊断、有限适配、评价报告；Skills 从动作案例提炼处理方法、工具和验收要求，本阶段不编写实际 Skill 文件。

运行分三段：**历史资料上的方案构建与适配 → 冻结方案后的逐日起报 → 独立只读评价。** 起报时不读取未来流量真值；独立测试不反向调参。资料正常或调整无效时允许维持方案，不要求每轮都优化。

## 五、如何证明减少人工

设置三个主组：H 为人员使用共同工具；P 为固定自动化流程；A 为业务动作 Agent。资源允许时增加通用 Agent 消融组。三组使用相同数据、模型起点、工具、优化空间和计算预算。

计划 15 个正式任务包，覆盖正常、资料异常、运行异常、模型偏差和证据不足。开发案例与正式任务分开，真实问题与注入故障分别报告。

主指标是人员主动工时，包含准备、核查、接管、纠错和最终复核；计算等待另计。同时评价预报质量、合格完成率、错误干预、无效试验和 API 费用。失败任务保留，不能只统计成功案例的节省比例。

15 个任务用于探索性工程验证，不预先承诺统计显著。若参与者只有学生，结论限定为学生或模型使用者的操作负担；专业人员减负需另有专业人员对照。

## 六、实施与交付

依次完成模型与数据门槛、共同工具、固定 Pipeline 与先导任务、主 Agent、实验冻结、H/P/A 比较及网页答辩。先验证一次真实推理和微调，再扩大开发。

交付预报工作台、可复现方案与预测、完整动作和成本账本、对照结论、结题报告及答辩 PPT。网页突出过程线、处理证据、方案采用/撤销和工时对比。未提升或 Agent 不如固定流程同样如实报告，但不代替完整实验。

希望导师重点指导：业务动作是否合理；质量容忍门槛如何设定；能否核对少量典型处理案例并确定真人实验对象。
