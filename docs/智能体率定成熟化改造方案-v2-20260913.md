# 智能体率定成熟化改造方案 v2

日期：2026-09-13。审查代码基线：`2ef6c5b`。状态：待实施设计，不代表能力已实现。

## 1. 目标、范围和基本原则

面向腰古 `yaogu` 与 Leaf River `usgs_02472000`，交付可持续搜索、可复现、可恢复、能诚实解释失败的率定系统。保留老师 XAJ 内核与来源校验；本期验证集总执行路径，不宣称分布式率定。Lowman 历史结果不作为这两个流域的证据。

产品默认行为：在用户授权的预算内持续寻找更优方案；合格不自动等于收敛；预算耗尽不自动等于收敛；未通过发布条件不抹掉搜索进展。

成熟性由五个条件共同定义：数据和评价可信、数值优化有效、实验决策有依据、工程执行可靠、实际两流域验收成立。更多 Agent、更多策略和更多报告字段不直接构成成熟性。

- 老师内核适配、数值搜索和 Agent 职责分离。

## 2. 目标架构：执行由服务掌握，Agent 负责受控实验决策

```text
复核模型方案与数据
  → 锁定 CalibrationProtocol
  → 连续基线与数值正确性检查
  → CalibrationCampaign
      诊断 → 提议实验 → 确定性校验 → 数值搜索与检查点
        ↑                                  ↓
      反思 ← 有限 development 选优 ← 候选档案与阶段总结
  → 搜索终止与最终选定
  → 冻结协议、模型、参数、数据与规则
  → final test → 资格与报告
```

API、CLI、smoke、固定优化器基线、规则科学家和真实 LLM 共用 runtime factory、协议、模拟器、指标和账本。只允许替换实验决策 provider；不能为 smoke 单独实现更完整的科学闭环。

先单任务、单数值 worker 打通确定性恢复，再加入受预算协调的并行执行。不以多 Agent 作为本期依赖。

## 3. 契约与唯一事实源

| 对象 | 必须保存 | 不变量 |
|---|---|---|
| CalibrationProtocol | 版本、流域、模型/方案/数据/质量哈希、执行表示、日界、蒸发语义、四窗口、指标、事件规则、选优规则、预算与 seeds | 开始搜索后不可原地更改 |
| Campaign | 协议引用、任务状态、全局预算、search_best/selected_best/release_candidate、停止原因 | 初始方案永久可追溯 |
| ExperimentPlan | 假设、证据引用、预期、策略/参数组/优化器、目标 profile、seed、预算、初值来源、checkpoint | 拟议与执行计划均保留 |
| NumericalTrial | 参数、目标分量、有效性、拒绝原因、模型调用、耗时、缓存、来源、时间 | 每次尝试可审计，不只保留改善轨迹 |
| ExperimentResult | 搜索总结、Top-K、边界/敏感性、cal/development 证据、预算、停止原因 | 与 plan、protocol、数据版本一致 |
| SelectionDecision | 候选集合、选择规则版本、主指标差、逐项护栏、样本数、采用与资格 | 不能只有 ACCEPT/ROLLBACK 文本 |
| Checkpoint | 优化器完整状态、随机数状态、trial 游标、预算、哈希与校验和 | 不兼容版本禁止直接续算 |
| FinalTestRecord | 冻结引用、暴露记录、运行状态、指标与产物哈希 | 不回流同一 campaign 的选择过程 |

新增对象优先作为版本化领域契约和服务，不强制一开始拆成微服务。数据库保存状态与索引，不可变文件保存大型序列和数值账本；元数据更新事务化。

## 4. 数据协议：先堵住影响结论的漏洞

### 4.1 四窗口与目标日期隔离

- 明确 warmup、calibration、development、final_test 起止日期，取消正式研究的 90 天业务上限；保留资源预算保护。
- 模型可使用历史强迫推进状态，warmup 不评分；不允许用未来观测初始化状态。
- 正式连续模拟以目标日期评分。滚动预报另定义 issue、target、lead：每条 lead 的目标日期必须属于当前窗口，必要时将起报集合前移。
- 禁止只裁剪末尾后继续假定每条 lead 样本数相同；每条 lead 单独统计可用性与覆盖。
- 最终评价快照按协议所需历史构建，不再使用 warmup + 60 的固定长度。
- 小窗口只标 smoke/insufficient_evidence，不能因为 3+3+3 天满足长度算式就标正式研究。

验收：保持强迫不变，任意修改 final-test 观测，冻结前候选、评分、排序、Agent 可见证据和决策输入必须不变。分别覆盖开发期末日的 lead 1/2/3。真实 LLM 可验证输入完全一致，再通过录制响应回放验证执行结果，不要求随机生成文本逐字一致。

### 4.2 质量、时间与空间语义

- FlowObservation 增加 quality、imputation_method、eligible_for_scoring；缺测允许明确表示，不以插补伪装实测。
- snapshot manifest、CSV/列式产物、观测 loader、优化与所有评价共同保留质量掩码。
- 插补值可按协议用于上下文或展示，但正式观测评分默认排除；包含插补值的敏感性报告单列。
- 验证单位、流域面积、面积加权、连续日期、重复日期、缺测、异常负流量、日界和时区。
- 腰古实测蒸发与 Leaf River PET 使用不同语义标签与先验兼容键；不通过平移日期或事后改转换提高分数。
- execution_representation 写明 lumped；多单元方案被聚合后不能继续标为已验证 distributed。

验收：Leaf River 2016-11-27 在每条实际评分路径中被排除，原始样本、有效样本、排除原因可逐日重算。

## 5. 模拟与指标：让搜索、诊断和评价说同一种话

### 5.1 统一连续模拟服务

- 建立真正拥有执行能力的 ContinuousSimulationService，而不仅是接收数组的 scorer。
- 一次加载强迫，按同一初始化规范连续推进；按协议切片产生 cal/development/final 证据。
- 单次运行、分块运行、checkpoint 恢复、老师参考输出必须在规定数值容差内等价。
- 缓存绑定模型/方案/强迫/参数/时间步/初始状态/执行表示。模拟缓存不依赖观测；评分缓存额外绑定观测、mask、窗口、指标版本。
- 长序列缓存不为每个 trial 永久驻留完整过程线；保留当前最优/Top-K，其他可重算或受限落盘，设置内存和磁盘配额。
- R 历史回算与 F 业务预报分开报告；不得把事后强迫的结果包装为业务预报能力。

### 5.2 预注册指标 profile

首版采用固定的连续 NSE 主指标，KGE 及分量、PBIAS、RMSE、低流量、事件峰值/峰时/洪量作为独立诊断和明确护栏。若业务选择 KGE 为主指标，则整个 campaign 固定该 profile；不可在实验中随意切换目标并把不同目标值比较为“进步”。

- 样本不足、常流导致 NSE 分母为零、指标不可计算均是显式状态，不能替换成 0 或误认水文失败。
- 全期与分年、季节、洪水事件评价分开。事件识别规则、分离规则、低流阈值、时间尺度运行前锁定。
- 峰时使用真实日期差，不使用删掉缺测后的数组索引差；有缺口的事件不可拼接成连续洪水。
- 日模型评价日尺度峰时，不虚构小时精度。
- 高流量护栏按足够独立事件评价；仅一个分位点不支持稳定“高流量能力退化”的判断。
- 报告中的连续指标和 rolling lead 指标不得共用无说明的 NSE 字段。

## 6. 最优解管理与 Gate 重构

### 6.1 三个“最好”，初始方案永远只是候选之一

| 状态 | 定义 | 更新方式 |
|---|---|---|
| search_best | 同一固定 cal 目标下已找到的最佳可行解 | 数值搜索内部严格改善就更新，与是否合格无关 |
| selected_best | 按预注册 development 规则选出的最佳方案 | 只在预定检查点、有限候选集合中比较 |
| release_candidate | selected_best 通过规定资格后的发布候选 | 可以为空，不能用默认参数自动填充 |

默认参数以 initial_baseline 不可变保存。search_best 不通过 development 时仍留在数值搜索档案，但不自动替代 selected_best。下一阶段可从 search_best、selected_best 或多样性档案启动，来源必须可追溯。

### 6.2 硬约束、排序、资格分开

1. 硬约束：参数/数值/数据契约、预先认定不可接受的业务损害。失败可行性筛选，不因高主分数放过。
2. 排序：在可行候选中按固定主目标及明确 tie-break 选优。多目标需求另建预注册 Pareto profile，不能让 LLM 临时调权重。
3. 统计与稳定性：样本不足标证据不足。需要不确定性时按水文年或独立事件做成组重采样，不把日样本当独立观测。
4. 资格：是否达到业务/标准门槛，与搜索改善独立。

不建议直接删除当前高流量护栏，也不凭空将 5% 换成更宽数值。先确定事件样本与误差尺度，再预注册相对和必要的绝对容差；基线误差接近零时不能单独使用相对比值。

采用审计至少输出：base/candidate 每项值、差值、样本数、阈值、结果和原因。禁止把“总体改善但局部护栏失败”写成“候选全面退化”。

search_best 可接受任意严格数值改善；selected_best 为防数值噪声或频繁替换可采用明确的等价容差，两者不是同一个阈值。

## 7. 持续优化与操作性收敛

### 7.1 Campaign，而非固定两轮对话

移除“正式研究只能 2/4 个实验”和“20 轮对话决定率定寿命”的隐含终止语义。保留数值评估、计算时间、Agent 调用次数等显式资源上限；不同模式各自有预算。

- smoke：小预算验证接线，不报告收敛。
- target_quality：达到预注册质量及稳定条件可结束，不称为搜索收敛。
- convergence：默认正式模式；达到合格线仍继续，在操作性收敛或资源边界停止。

先做合法性检查、真实强迫合成恢复和敏感性诊断，再做全局探索、局部细化、多起点验证。Agent 不在每个 numerical trial 介入，只在批次检查点评估下一实验。

### 7.2 优化器适配与恢复

统一接口：initialize、ask/tell 或 step、checkpoint、restore、summarize。DDS 保存 RNG、已用次数、预定总 schedule、最优点等；SCE-UA 保存种群、分数、complex 状态、RNG、计数。不能只保存最优参数就称“断点恢复”。

DDS 的扰动概率依赖预定总预算。原定 512 次跑完后追加 512 次，不等价于从头规划的 1024 次：应预注册总 schedule 并分块执行，或显式创建新的 warm-start 阶段。预算扩展不能偷偷改变历史算法定义。

所有比较中的优化器必须同口径处理整数参数、边界、非法候选和目标方向；独立参照实现用于验证本地 DDS/SCE-UA 行为，具体版本在实现阶段核验并锁定。

### 7.3 收敛与停止

收敛不宣称全局最优。定义“在指定搜索范围、算法、预算与重启检查下，满足预注册改善容差”。

ConvergencePolicy 必须包含：最小有效评估数、检查批大小、绝对/相对改善容差、连续平台批数、重启验证要求、总预算与 wall time。具体数字通过两流域预实验和成本测量决定，正式运行前锁定，不观察 final test 调整。

检查逻辑：

1. 未达到最低探索量不能报收敛。
2. 最近若干批次 cal best 改善小于容差，标 plateau_candidate，而非立即收敛。
3. 检查有效新候选比例、缓存/非法率与边界命中；无新搜索是 stalled，不能伪装稳定。
4. 用预注册的不同起点/seed 或受控扩大搜索检验平台；发现显著改善则继续。
5. 达到全部条件才 reported_converged；边界可疑但无扩展权限应写 unresolved_boundary/stalled，不偷偷越界。
6. 预算用尽仍改善时返回 budget_exhausted + not_converged，保留可恢复状态。

数值收敛主要在 cal 上判断，不能每个 trial 都看 development 或 final test。development 的检查次数和进入集合的候选数有独立上限。

## 8. 预算、账本、缓存与故障恢复

- 区分 proposal、非法拒绝、score call、cache hit、真实 model execution、成功/失败 model execution；真实调用开始时计费，失败也占资源。
- 硬预算分别限制搜索模型执行、总模型执行、逻辑尝试和 wall time，避免缓存/非法候选造成无限循环。
- Morris、预热、基线、候选 development 和报告计算的费用各自列账；同预算对照明确搜索预算和总成本两种口径，不能把某组的敏感性开销藏掉。
- 并行 worker 先原子预留预算再执行；取消后不再分配新 trial，允许记录已在运行的任务并约束最大超额。
- 缓存命中不声称新增模型信息；跨实验复用必须校验完整 fingerprint。
- checkpoint 原子写入，含 checksum 与版本；恢复时先重放未提交事件，幂等更新最优指针和 trial 游标。
- experiment_id / trial_id / final_test_id 幂等。服务重启、网络断开、重复消息不能重复采用、重复扣费或重复写案例。
- A12 允许同一冻结产物的确定性重算或报告修复；不可将“final test 单次使用”实现为失败后永不可恢复。暴露状态在访问观测时记录，与任务成功状态分开。
- 模型进程保留超时、内存、输出配额和凭证隔离。长任务用 worker/队列、心跳、取消与恢复，不直接取消安全时限。

## 9. Agent 权限、证据与真正的增益

Agent 输入：cal 全期诊断、有限 development 反馈、敏感性/边界/覆盖、当前最优、既往实验、剩余预算与可用操作。禁止 final-test 指标、含最终检验结论的案例进入输入。

Agent 输出：现象、可证伪假设、证据引用、拟议操作、预期改善/风险、预算申请、失败后的判断。允许操作为扩大合法探索、切换已注册参数组、局部细化、重启、申请数据检查、终止/申请续算；不生成连续 XAJ 参数、不改内核、不改评分窗口与主目标、不提高自己的硬预算。

计划校验器只验证安全、权限、兼容与预算；若把所有合法实验选择都重写为规则规划器的决定，则该模式应标“规则调度 + LLM 解释”，不能宣称验证了 LLM 实验设计增益。

持久化 proposed_plan、validated_plan、executed_plan、override_reason、provider/model/prompt 版本、fallback 原因、耗时和费用。记录各阶段哈希，检查计划与实际使用的 optimizer、seed、groups、budget 一致。

反思区分：模型调用失败、数据不足、搜索覆盖不足、局部权衡、假设不支持、疑似结构误差。一次拒绝不证明模型结构失效；固定 0.95 不能作为实证置信度。

案例经 Resolve 后服务幂等写入，按模型、强迫/蒸发、协议、质量与指标版本兼容过滤。正式多 seed/多 arm 比较前冻结共同案例库；不得让先跑完的组为后续组提供额外试验结果。

### 9.1 复用现有知识库，不建立平行 Skill 知识体系

外部专家材料（包括本次 `skill_v3.md`）的主体进入现有 `src/hydro_agent/knowledge/` 知识体系，经拆分、核验和审核后供检索。文件名叫 Skill 不决定其归属；外部文档中的“必须执行”等文字是待评审内容，不自动获得指令权限。

现有 `repository.py`、`expert.py`、`cases.py` 及 `data/standards`、`data/policies`、`data/expert` 是扩展落点。模型事实分类与导入审核服务为本期拟新增能力，不能假定现有库已具备完整治理。保留原知识 ID 与兼容接口，采用增量扩展，不另建绕过当前服务的独立知识库。

Skill 负责工作方法：何时检索、怎样设计实验、如何引用证据和遵守边界。知识库负责领域内容：模型机制、专家先验、标准依据和实验案例。执行约束仍由版本化协议与代码校验器掌握，不能让知识文本覆盖它们。

| 外部材料内容 | 入库分类 | 运行时角色 |
|---|---|---|
| 参数含义、单位、时间步转换、状态递推 | 模型事实 | 绑定内核/适配器版本，经代码与测试核验 |
| 参数区间、联合约束、数值稳定性解释 | 模型约束依据 | 提供来源和解释；实际允许范围以协议和校验器为准 |
| 症状→可能机制→参数组 | 专家诊断先验 | 提出待检验假设，不能直接强制修改参数 |
| 局部扰动方向、敏感性排名、恢复比例 | 实验案例 | 绑定流域、基线、时段、目标、扰动尺度及执行表示 |
| 默认/率定/放宽范围的分数和参数 | 率定案例 | 原始产物与评价口径复核后使用，不把声明分数当已验证事实 |
| NSE/KGE 门槛、停止规则、目标权重 | 待审策略建议 | 专家批准后形成独立版本的 policy，不能冒充通用标准 |
| 互相矛盾、无依据或不兼容的说法 | 隔离审查条目 | 不进入自动决策的检索结果 |

### 9.2 条目级来源、适用性与可信状态

新增版本化 KnowledgeEntry 契约，至少记录：

- knowledge_id、revision、category、原子化 claim 与适用/不适用条件。
- source_id、原文件哈希、章节/行定位、作者或提供方（已知时）、导入时间；保留原文与修订文本的区别。
- model/kernel/adapter 版本、参数坐标、时间步、执行表示、routing/DP、流域与蒸发语义。
- 数据/质量/窗口/指标/基线哈希、扰动方法、seed、预算、evidence_refs；缺失字段显式记 unknown，不能推断补齐。
- verification_status、review_status、验证脚本/报告哈希、审核人/时间、冲突关系与 supersedes。
- calibration/development/final_test 暴露标签及禁止用于选择的范围；关联结果的派生结论继承暴露标签。

可信状态建议为 unverified、verified_in_scope、disputed、rejected、superseded；人工审核状态另设 pending/approved，避免把“审核过”和“已实验验证”混为一谈。验证通过只作用于该条声明和限定范围，不能给整篇材料自动盖章。

数值效果与敏感性案例须有可复核证据；经验先验可经专家批准后以“未实证的先验”参与假设生成，但不得输出成既定事实。rejected/disputed 条目默认不进入自动规划，仅在显式审计中可见。

### 9.3 导入、检索与实验反馈闭环

导入流程：原文只读归档 → 提取原子声明 → 分类与去重 → 公式/单位/契约冲突检查 → 需要时复现实验 → 条目审核 → 发布知识版本。重复导入同一 source hash 不产生重复条目；矛盾不得通过覆盖旧文本消失，应建立 conflicts_with/supersedes 关系。

检索流程：先按可信状态、模型兼容性、数据语义和暴露权限过滤，再做语义相关性排序。腰古局部敏感性不能作为 Leaf River 的已验证排名；不兼容材料如需参考，只能走明确标注的跨域假设通道，不能携带数值先验直接执行。无兼容结果时返回“无适用知识”，使用已注册基线，不放松过滤来凑结果。

Agent 接收 KnowledgeEvidenceBundle：条目 ID/版本、原文位置、适用条件、可信状态、证据与局限。记录 retrieval_run_id、query/context hash、知识快照、返回条目及实际引用条目，使“检索到”与“采用为依据”可区分。

实验后先把结果写为案例，成功、失败与无结论均保留。不得由一次改善自动晋升通用专家规则；规则晋升需预先规定的多时段/多初值或独立案例支持、反例检查及人工审核。知识变更不原地影响进行中的 campaign：新任务绑定新快照，当前任务若需切换须显式记录协议/知识版本变更。

final-test 结果可进入隔离的最终评价记录，但不能回流同一 campaign 或同轮 O/P/A 比较。后续开发若使用这些结果，必须继承已暴露状态，不能把相同年份重新命名为独立 test。

### 9.4 `skill_v3.md` 作为首批待审材料的处理方案

本次仅设计入库流程，不执行导入，也不把其“全部 PASS”视为本项目已验证。第一批抽取参数机制、诊断先验、腰古局部敏感性和率定案例；索取 audit 脚本、原始逐日结果、A/B 参数、数据与实际评价日期掩码后，再进行逐项复核。

优先隔离或更正：KE 稳定范围前后不一致、PBIAS 与水量项重复及峰值误差单位问题、KI+KG 边界与当前契约冲突、DP 只读与建议修改的矛盾、峰现偏晚却建议增加 LAG、验证期反复选优仍称独立检验，以及将局部敏感性排序泛化为固定参数纪律。

文中 NSE 0.770/0.887 等只作为待核验案例声明；若复现，则用一致协议比较与当前系统差异，不直接写成两个流域的统一目标或验收阈值。KE/XE 是否应加入搜索作为待验证实验假设，不因外部文字自动开放参数权限。

## 10. 两流域实验设计与可归因比较

### 四阶段验收

1. 正确性：老师核对、状态连续、掩码、窗口隔离、目标方向、合成输出恢复。
2. 数值基线：两流域完整历史、预热、合法参数、固定优化器、多 seed、收敛与耗时曲线；先证明不依赖 Agent 也能正常率定。
3. Agent 增益：同协议同预算，比较固定调度、规则调度、真实 LLM；两个流域只支持案例结论，不作大范围泛化宣称。
4. 消融：只有完整链路有效后，测试无记忆、无敏感性等组件，避免一开始铺开八组但没有可运行 executor。

### 数据分割候选

| 流域 | warmup | calibration | development | final test |
|---|---|---|---|---|
| 腰古 | 1989 | 1990—1997 | 1998—2000 | 2001—2003 |
| Leaf River | 1979 | 1980—2004 | 2005—2014 | 2015—2025 |

这些只是覆盖候选，不直接启用。需核验日期、预热充分性、源数据和既往暴露。已被用于调策略的年份不能因为新建 task 就重新称“从未见过”；无法获得未暴露数据时采用明确标注的回顾性分块评价，未来前瞻验证另行安排。

### 对照的公平性

- O/P/A 的核心差异只放在调度方式。主比较使用同一优化器或同一可用算法集合；O=SCE-UA、A=DDS 的结果只能解释为整套系统差异。
- 同流域同 replicate 共享种子计划；优化器路径不同不保证相同随机数消费，但不能无说明给各组完全不同 seed 再宣称严格配对。
- 各 arm 使用独立数据库/工作区、相同初始案例库和协议，不共享当前实验产生的 development/final 结论。
- 先预实验测 256/1024/4096 等预算阶梯和成本，再锁定正式预算；这些数字不是收敛保证。
- 至少多 seed 检查，3 seeds 只作初始稳定性检查，不自动代表统计显著。正式数量由变异与可用成本决定。
- 报告所有运行，含失败、未完成、预算耗尽、未收敛；平均分/胜率同时给样本分母与完成率，不通过丢弃失败提高表现。
- suite 执行、导入和汇总共用 strict validator，验证完整 manifest、seed、scenario、arm、预算、最终检验暴露与产物哈希，拒绝伪造成功记录。
- 同时回答两个问题：固定资源下谁更好；达到固定目标谁成本更低。未优于 O/P 时，产品保留便宜可靠的固定/规则模式。

## 11. 产品交互、迁移与可观测性

- 主页面显示“运行中/平台检查/已收敛/预算耗尽未收敛/证据不足/失败/取消”，采用和资格另列。
- 默认展示 initial、search_best、selected_best；release_candidate 为空时直接说明没有可发布方案。
- 图表按 cal/development/final 切换，注明样本、掩码、是否参与选择和基线来源；final 在冻结前不可见。
- 显示 best-so-far 曲线，区分 cal 与有限 development 检查点；显示真实执行、缓存、失败、预算剩余与时间估计。
- “保留初始方案”说明具体原因，不显示“默认参数最优”；失败指标可展开到对应事件和日期。
- 提供暂停、恢复、取消、经授权追加预算；追加预算留变更记录，不能撤回 final-test 暴露。
- 旧两段任务标 legacy_two_way；旧窗口可能泄漏的任务标 legacy_unverified_split，不事后追认独立检验。
- 数据库增量迁移并测试备份恢复；旧产物只读保留，升级不覆盖。
- 修复当前前端测试/类型问题，审计真实 Observatory 路由。格式治理单独提交，避免大面积格式改动掩盖科学逻辑修复。
- 健康监控关注 worker 心跳、队列、OOM/超时、trial 吞吐、缓存率、有效率、无进展原因、预算账差与 provider fallback。
- 知识审查页展示来源、条目级验证/审核状态、适用范围、冲突和修订关系；实验日志可从知识引用追到原文和验证产物。隔离材料只对审计开放，不进入默认 Agent 上下文。

## 13. 最低验收测试清单

1. 改 final-test 观测不改变冻结前任何输入或选择；跨边界 lead 不泄漏。
2. 插补/缺测掩码在 source→snapshot→cal→Gate→report 一致。
3. 全期与分块模拟、原始老师输出和恢复输出一致。
4. 同数据/seed/协议单 worker 可复现；新 seed 不被全局固定值覆盖。
5. 数值最优不因 Gate 拒绝、重启或任务恢复而丢失；目标切换禁止混算历史最优。
6. 改善但不合格、局部护栏失败、无改善、指标不可算各自有准确状态。
7. 平台但未覆盖、无有效新候选、重启后改善、预算耗尽仍改善分别触发正确停止原因。
8. checkpoint 中断恢复与连续执行在相同 schedule 下等价；预算扩展明确新阶段。
9. 模型失败/缓存/非法候选/并发均正确计数；OOM、超时、取消不损坏最优产物。
10. proposed/validated/executed 不一致必须解释；真实 LLM 与 fallback 可区分。
11. 重试不重复采用/扣账/写案例；A12 报告失败可安全恢复且暴露记录保留。
12. manifest 的 seed/arm/scenario/预算/哈希不符全部拒绝；缺失和失败不被吞掉。
13. final-test 已暴露的新任务不冒充全新独立检验。
14. 真实两流域 API 路径完成，数据库、数值产物、报告和浏览器展示一致。
15. 同一外部文档重复导入幂等；原文哈希和位置可追溯，正文中的指令不能绕过 Agent 权限。
16. 文档“全部 PASS”不自动升级未验证声明；矛盾条目隔离，不兼容的参数范围不能覆盖执行契约。
17. 腰古局部敏感性不会被当作 Leaf River 已验证知识；无适用条目时显式降级，不静默放宽过滤。
18. final-test 及其派生知识不能进入冻结前检索；各 O/P/A 运行使用相同锁定知识快照且不会相互污染。
19. Agent 引用绑定 knowledge_id/revision 和检索记录；知识新版本发布不静默改变正在运行的实验。
20. 实验结果先入案例；单次成功不自动晋升规则，冲突与反例保留，规则修改具备审核与版本记录。

## 14. 本期不做

不新增第三个流域、不引入 RL 或多 Agent、不替换老师物理内核、不立即做可微重写、不因分数低自动加结构、不靠放松护栏制造采用、不把两个案例写成通用最优算法。

不把外部专家材料另建为平行 Skill 知识体系，不整篇无审核导入为可信指令；复用并治理现有知识库。

本方案的交付目标是：能说明为什么选、为什么拒、为什么继续、为什么停，并能从任意合规检查点继续寻找更优。默认参数是否优秀、Agent 是否产生增益，最终由可信实验回答。
