# 预报问题—诊断依据—处理动作—效果验证设计

**用途：** 为“基于智能体的水文预报方案构建及参数优化”确定 Agent 实际承担的业务工作，作为后续工具与体系内 Skills 的设计依据。

**日期：** 2026 年 9 月 7 日。

**状态：** 仅设计；下列动作不是已实现的工具、算法或 Skill。

**主方案：** [V1.0 开发实施方案](基于智能体的水文预报方案构建及参数优化系统%20V1.0%20开发实施方案.md)。

## 1. 先定义 Agent 的任务

Agent 接受一次已配置的任务，由任务事件与历史时钟持续驱动：准备资料和模型，在允许的历史开发资料上诊断改进，冻结方案，完成指定日期的逐日流量预报，最后生成独立评价与结论。

不是等用户提出某个洪峰问题才开始工作。程序例行检查发现问题后，Agent 自主判断该查什么、做什么、是否值得继续。资料和模型正常时直接预报。

## 2. 动作的共同契约

每次动作保存：

- **任务与阶段：** mission_id、experiment_id、起报时刻、开发/独立回测/报告阶段。
- **触发事实：** 已发生的事件或已计算的指标，附 evidence_id，不把猜测写成事实。
- **输入：** 数据、方案、模型与先前结果的版本化引用。
- **诊断假设：** 可能原因、其他解释、证据是否足够。
- **动作：** action_id、选择理由、可修改对象及具体值、预期影响。
- **权限与成本：** 阶段允许性、时间与尝试额度、工具白名单。
- **执行证据：** 任务状态、日志、输入/输出摘要、实际变化、消耗。
- **核验：** 是否按要求执行、目标问题是否改善、其他指标是否退化。
- **下一步：** 使用、撤销、另行排查、停止或报告受阻。

禁止用“调用工具成功”代替“问题解决”。动作核验分四层：工具完成、产物合法、目标问题改善、是否满足方案采用条件。

## 3. 问题与处理路径总表

| 问题/事件 | 必看证据 | 优先动作 | 可改变对象 | 核验 | 无法解决时 |
|---|---|---|---|---|---|
| 首次任务启动 | 任务范围、资料目录、权重来源 | A01 → A03 | 合法方案配置 | 数据/权重兼容、能够运行 | A09 说明缺口 |
| 缺文件、单位或时序异常 | 原始来源、元数据、重复与缺测报告 | A01 → A02 | 有证据的派生数据与缓存 | 语义正确、来源可追溯 | 拒绝伪造，记录缺失 |
| 起报窗口或状态缓存不匹配 | 历史窗口、输入与权重摘要 | A04 | 计算状态及其缓存 | 同条件历史重算一致 | 停用缓存或 A09 |
| 正常起报 | 当前合法输入、冻结方案 | A05 | 仅生成预测 | 键、长度、单位、有限值 | 处理执行问题，不乱调参数 |
| 整体偏大/偏小 | 多事件偏差、单位和输入量级 | A06，必要时 A02/A07 | 先查资料，再有条件适配 | 同口径偏差与整体指标 | 保留基线并说明限制 |
| 洪峰偏低/偏高 | 固定事件匹配、气象资料、峰时/水量 | A06 → 条件成立才 A07 | 合法微调配置 | 峰值及其他指标一起检查 | 不因单场结果断定根因 |
| 峰现时间偏移 | issue/valid_time、lead、日聚合与气象时序 | A06 → A02 | 仅确证的时间处理错误 | 对齐正确且重算可追溯 | 无直接时序纠偏动作时 A09 |
| 退水过程偏差 | 事件尾部、后续降雨、训练/验证表现 | A06 | 首先只补充诊断证据 | 排除资料/事件划分问题 | 不虚构 LSTM 退水系数 |
| 微调不稳定或退化 | epoch 指标、梯度、模块变化 | A06 → A07 → A08 | 训练强度或模块配置 | 按冻结规则采用/拒绝 | A09，恢复已验证方案 |
| 预算结束或无需改进 | 最佳结果、成本、未解决问题 | A10 | 推荐方案引用 | 已完成证据齐全 | 有结果就明确收尾 |
| 历史时钟推进 | 下一个起报时刻、输入可得性 | A11 调用 A01/A04/A05 | 当前起报记录 | 完整覆盖指定日期 | 每个失败日期留记录 |
| 全部起报完成 | 冻结结果、独立测试输出 | A12 | 只读报告与图表 | 结论可追溯 | 明确未证实事项 |

问题与动作不是一一对应。没有证据表明参数有问题时，不进入微调；同一个现象可以通过不同排查路径得出不同结论。

## 4. A01：检查资料与预报条件

**触发：** 首次启动、每次起报、输入版本变化或结果异常。

**输入与判断：** 检查必需变量、日期覆盖、发布日期、时区、单位、站点/流域 ID、负值/缺测标记、文件摘要、权重训练范围及配置要求。识别正常、可自动处理、当前不可处理三类问题。

**允许动作：** 读取数据和元数据、生成质量报告，决定直接进入预报、转 A02 修复，或停止当前任务。开发阶段可筛选候选流域；目标冻结后不能因测试表现差换流域。

**核验：** 报告必须指出具体文件/字段/日期及检查规则。异常幅度本身不证明数据错误；真实洪峰不能仅因超过统计阈值就删除。

**输出与后续：** 质量报告、可用性标签和待办列表。必要输入缺失则转 A02；无法恢复则 A09，不能把缺失降雨默认为零。

## 5. A02：有依据地补取或纠正资料

**触发：** A01/A06 给出确证的问题，例如源单位与转换不符、缓存文件损坏、可重新下载的资料缺失。

**输入与判断：** 原始数据、来源说明、合法处理规则、允许读取的时间范围。区分“记录存在错误”和“观测可能偏差但无校正依据”。

**允许动作：** 重取指定文件、去除确证重复、依据元数据转换单位或统一时间；按预先确认的规则处理输入缺失。每次形成派生版本和处理记录，保留原始数据。

**约束：** 不凭流量拟合效果调整降雨，不利用起报后的观测做双向插值；不插值测试流量作真值。测试期间只能执行冻结的数据处理规则，发现需改变语义规则时暂停相关日期并报告，不临时改协议。

**核验：** 对照源数据和转换公式，检查只改变指定项；重算应使用同一模型。数据修复与模型微调不能同时进行而混淆收益。

**输出与后续：** 新数据摘要和正确性证据，转 A04/A05。在正式比较前发现数据版本需修订时，统一更新所有方法基线后再开始比较。

## 6. A03：建立可执行预报方案

**触发：** 无可用方案，或开发阶段已确认原方案与数据不兼容。

**输入与判断：** 任务、数据报告、上游模型能力、权重训练范围、CPU/MPS 门槛记录。判断是否可复用合法权重，或必须基于官方小模型先训练基础模型。

**允许动作：** 从已验证模板中选择模型/权重组合，配置变量映射、历史窗口、预见期、输出解析和预算，执行小时间窗试运行。确需基础训练时使用训练期数据并计入启动成本。

**约束：** 架构与输入维度须匹配权重；不能任意删掉所需变量，也不能以未知训练范围的权重证明独立测试。基础方案确定后冻结供各方法共享。

**核验：** 真实加载与前向运行，核对预测键、实际 head、点预测归约与单位，取得可重复的基础结果。教程旧结果只能作为联调资料。

**输出与后续：** 可执行方案、基础产物和来源报告，进入 A04/A05；受阻转 A09。方案可用不代表精度优秀，精度由后续验证决定。

## 7. A04：重建起报历史计算条件

**触发：** 首次起报、窗口缺失、模型版本变化，或缓存摘要不匹配。

**输入与判断：** 当前起报时刻、合法历史窗口、模型/数据版本、计算窗口配置。判断是否具备完整历史，已有缓存是否属于同一模型与相应时段。

**允许动作：** 首期采用完整历史窗口重新计算模型历史部分，清除或隔离失配缓存；训练权重改变后重新建立相应起报条件。

**约束：** 不任意增减历史长度来“调峰”；改变窗口规则属于开发期方案试验。模型隐藏状态没有直接的物理单位，不允许 LLM 给某个维度填入所谓土壤含水量。

**核验：** 同一输入、权重及设备条件下重算应在冻结容差内一致。检查窗口最后时刻不超过允许边界。已有 hot-start 接口可作为后续优化，但必须先证明与完整历史重算的一致性及无时间泄漏。

**输出与后续：** 起报输入/状态来源引用、重算日志，转 A05。资料不足则 A02/A09。该动作不声称修正了真实土壤水状态。

## 8. A05：执行预报并检查产物

**触发：** 当前日期已具备合法方案与输入，正常情况下直接执行。

**输入与判断：** 起报时刻、未来气象输入、历史计算条件与输出协议。

**允许动作：** 调用 OpenHydroNet 推理，解析未来 1、2、3 日流量，检查唯一键、有限值、负值处理规则、长度、单位和模型版本。模型原生输出更长预见期时保留原始输出，主评价仍按协议选前三日。

**约束：** 质量判断只能使用起报时刻的信息和冻结的检查规则。预测很高不等于计算失败；不能为了降低误差而选择性不报。非负约束或 clip 如由上游启用，须记录原始输出与规则，各方法一致。

**核验：** 与受控直接推理结果对齐；每个有效时刻均能追溯至输入。技术失败允许有限重试；只有预先验证的兼容基线可作为回退，回退记录不得冒充当前方案成功。

**输出与后续：** 流量预测、质量标签和成本。在开发期由 A06 读取验证反馈；测试回放中只保存结果并推进日期，最终统一评价。

## 9. A06：诊断现象并选择处理方向

**触发：** 开发阶段完成验证运行、技术质量检查失败，或报告阶段需要解释已冻结结果。

**输入与判断：** 许可阶段的预测/观测、PBIAS、NSE、峰值/峰时/事件水量、训练曲线和数据报告。先区分执行错误、资料疑点、起报条件、持续模型偏差、局部事件和证据不足。

**允许动作：** 增补指标或事件核验、查询已核查方法与本实验历史，提出待验证原因，并选择 A02/A04/A07、维持方案或 A09。诊断本身不改变模型。

**约束：** “多场洪峰偏低”只能证明一种误差模式，不能直接确认降雨低估、融雪缺失或某层权重错误。报告阶段只形成建议，不能执行干预。

**核验：** 每项事实能定位到真实证据；有符号误差与绝对误差分开；多场一致性必须报告场次数和分布。没有证据时输出“不足以区分原因”。

**输出与后续：** 问题类型、候选解释、选定动作、被排除动作及原因。拟微调时明确要检验哪项假设。

## 10. A07：执行有诊断依据的模型适配试验

**触发：** 开发阶段存在可验证的模型适配假设，资料/起报问题已排查，且预算允许。

**输入与判断：** 诊断记录、冻结搜索空间、基础权重、训练资料和历史结果。解释调整学习率、训练长度或模块范围与试验假设的关系。

**允许动作：** 提交候选微调任务，改变白名单配置，由优化器更新选中权重。候选从共同基础状态开始，不在上轮权重上偷偷续训。

**约束：** 不手写权重、不改测试划分、不更换共享数据、不放宽目标、不任意修改网络结构。仅 head 与静态嵌入微调均是试验手段，不能保证纠正洪峰或峰现时间。

**核验：** 实际可训练参数列表符合预期；选中模块发生更新、冻结模块保持不变；任务有完整输出和成本记录。训练成功后还需 A08 验证效果。

**输出与后续：** 候选模型、训练日志、验证预测；转 A08。失败计入预算，按原因修复或 A09，不能通过不停重试扩大搜索额度。

## 11. A08：比较处理结果并采用或撤销

**触发：** A02/A04/A07 产生新版本或候选结果。

**输入与判断：** 处理前后证据、相同评价条件、目标误差、整体与事件指标、成本。先验证是否只改变了计划中的对象。

**允许动作：** 标记动作执行是否成功、目标问题是否改善、是否满足采用规则。接受只更新最佳方案引用，拒绝保留原引用及完整失败资料。

**约束：** 数据正确性不能仅用 NSE 判断。资料修复前后的结果另作因果受限说明；模型对照必须在相同合法输入上运行。无有效数据的指标不当成零误差。

**核验：** 使用主方案统一排名和退化约束；未解决的问题不能从报告删除。局部改善但整体不合格时如实记录并撤销。

**输出与后续：** 接受/拒绝、证据、局部收益与代价、下一步方向。回到 A06 或进入 A10；不能根据测试成绩调用本动作重新选模型。

## 12. A09：技术恢复、维持方案或报告能力不足

**触发：** API/worker 异常、预算不足、反复无效，或诊断需要当前模型不具备的动作。

**输入与判断：** 错误日志、动作状态、已完成产物、剩余额度、能力目录。

**允许动作：** 对可恢复技术问题有限重试；已有有效方案则维持；无法恢复时记录任务或日期受阻。下一动作必须有新依据，不重试完全相同的无效诊断。

**约束：** 不把 API 失败改标为水文模型失败；不把资料不足宣称为模型不适用；不临时转为新安江或全量重训而不变更研究范围。当前动作目录没有观测同化时，应明确能力缺口。

**核验：** 重试不重复训练/扣费/入账；恢复使用同一动作身份，终止保存已完成记录。

**输出与后续：** 可继续则返回原安全阶段；有基线则 A10/A11；无合法结果则 A12 形成受阻结论。无人提供下一条提示也能正确收尾。

## 13. A10：冻结推荐方案

**触发：** 改进阶段完成、预算结束、无新的可验证动作或无需继续处理。

**输入与判断：** 最佳合法方案、未解决问题、对照条件和完整预算。

**允许动作：** 冻结数据处理规则、权重/配置、起报规则、指标、动作权限和版本。没有优于基线的候选时采用基线并说明原因。

**核验：** 方案可重跑，所有推荐结论来自开发证据；各方法冻结条件一致。

**输出与后续：** 不可变方案清单与停止理由，转 A11。不能因最终成绩不理想而撤销冻结继续本轮调参。

## 14. A11：自动逐日起报

**触发：** 方案冻结，历史时钟推进到下一起报日。

**输入与判断：** 当前时刻合法资料、冻结方案、已完成日期清单。当前无异常则直接 A04/A05；可自动处理的问题仅按冻结规则调用 A01/A02/A09。

**约束：** 不访问测试目标真值；不通过未来资料修补过去预测；每个计划日期都有结果、回退或失败状态。过去已知流量只有在模型输入契约与时间可得性明确允许时才可使用，不能临时加入不支持的特征。

**核验：** issue_time/lead/valid_time 一致、日期无遗漏、预测写入后不可用未来数据覆盖。缓存重用与技术重试可做，但不得改变方案语义。

**输出与后续：** 起报序列与覆盖统计，直到运行时段结束后进入独立评价及 A12。

## 15. A12：形成预报评价、动作结论与答辩素材

**触发：** 全部起报完成或任务明确受阻。

**输入与判断：** 冻结结果、独立评价、动作账本、资料报告、成本和限制。报告流程只读，不能调用调参执行工具。

**允许动作：** 生成总体结果、各 lead 指标、事件案例、动作前后图、失败分类和后续建议。

**核验：** 图表数字与真实文件一致；每条结论区分“已确认事实、可能原因、尚不能回答”；没有真人对照不声称替代多少工时；没有重复实验不声称稳定优势。

**输出：** 报告、图表数据、PPT 素材、未解决问题清单及复现信息。典型事件按预先固定规则选择，如最大观测日流量事件和 lead=3 最大退化事件；不只展示最有利案例。

## 16. 三条示例路径（仅用于解释设计）

### 示例一：输入单位标记与转换不一致

A01 发现源单位与配置不符 → A02 按权威元数据纠正派生数据 → A04/A05 用原模型重算 → A08 检查量纲与结果。结论是修复资料处理问题，不能记为微调提升。若单位来源不明则 A09，不根据流量大小猜一个倍率。

### 示例二：多场验证事件洪峰偏低

A06 检查事件匹配、气象缺失、总水量与峰时 → 若缺资料先 A02；若未发现资料问题，可提出模型适配假设 → A07 在相同条件下试验 → A08 检查峰值及整体指标。无改善则撤销，不能断言“模型已修复洪峰响应”。

### 示例三：正常预报与能力边界

资料正常且当前方案有效 → A05 直接预报；不因存在 Agent 而强制微调。若出现需水文状态同化才能进一步检验的假设，当前只有状态存取接口 → A09 记录尚无相应处理能力；现有输出如合法可保留，不能伪造土壤水修正。

## 17. 从动作到 Skills 的推导方法

先用上述动作检验工具与输出，再把可以复用的完整工作方法聚合为 Skills。不是一个动作编号就对应一个 Skill，也不是把表格改名为 SKILL.md 即完成封装。

候选聚合方向：A01/A02 的资料检查与处理；A03/A04 的方案与起报准备；A06/A09 的排查与措施选择；A07/A08 的试验与复核；A10—A12 的方案交付、运行管理和结果解释。最终数量与名字在动作可执行性验证后确定。

每项 Skill 需明确何时使用、要读哪些证据、能调用哪些动作、每步产物与停止条件；运行时按阶段与权限加载。技能包不能改变上层预算、数据隔离或任务目标。本阶段不创建技能文件或代码。

## 18. 能力证据与验证清单

- 上游模型类可见 forward、模块定义和状态保存/加载：[Mean Embedding 源码](https://github.com/google-research/flood-forecasting/blob/828dfc5a66f4e6f2c86b09d500e4547c4d92ed25/googlehydrology/modelzoo/mean_embedding_forecast_lstm.py)、[Handoff 源码](https://github.com/google-research/flood-forecasting/blob/828dfc5a66f4e6f2c86b09d500e4547c4d92ed25/googlehydrology/modelzoo/handoff_forecast_lstm.py)。这是源码能力，不是本项目已完成的执行证据。
