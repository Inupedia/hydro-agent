# Hydro-Agent 产品规格（PROD）

**角色：** 产品实现的唯一依据。先做能力，再谈编排。

**修订日期：** 2026 年 9 月 7 日

**与课题方案的关系：** `docs/课题完整方案.md` 保留科研对照、O/P/A 与验收协议。本文件把那一层整段剥离。实现时只看本文件；课题方案不指导代码优先级。

**本期不做：** 方法组对照、90 次运行、A 对 P 增量证明、消融、文献贡献、答辩用的实验结论。

## 1. 产品是什么

用户创建一次预报任务后，系统自动完成：检查资料、校验方案、重建起报条件、跑模型、必要时做有限率定或局部适配、决定采用 / 撤销 / 停止、冻结方案、按日期回放、给出过程线和报告。

用户不逐轮点选 A01—A12。运行中可查看、暂停、恢复；能力不足时给出受阻包，而不是假装完成。

| 项目 | 首期产品 |
|---|---|
| 对象 | 一个公开流域，站点未来第 1、2、3 日流量 |
| 方式 | 历史起报回放；回放前冻结方案 |
| 模型 | 用户选定一个：`xaj` 或 `openhydronet`。任务中不切换、不集成 |
| 机器 | 一台 M1 Pro；本地单任务 |
| 交互 | 网页工作台 + 每个能力都有可单独调用的 API |

不是山洪预警、淹没、调度、全球训练、自动选模型。

---

## 2. 实现原则

1. **能力先于 Agent。** 每个 Tool 必须能用 API 单独跑通。没有 LLM 时，已经能检查数据、跑预报、做一次有限优化、出过程线。
2. **Agent 只编排。** 它选择下一个允许动作，不计算 NSE，不改原始文件，不生成 XAJ 参数向量，不自由设置 learning rate / epoch。
3. **工具结果必须留下。** 每次执行写入 `EvidencePacket` 和 `ActionLedger`。没有账本的能力不算交付。
4. **先交一个模型。** 哪个在 G0 先跑通真实 `forecast`，就先做哪个 Adapter；另一个后接，接口预留。
5. **停止是产品功能。** `ACCEPT` / `KEEP` / `ROLLBACK` / `BLOCK` 都是合法终态。

---

## 3. 用户路径

```text
创建任务
  → 自动运行（可暂停 / 恢复）
  → 工作台看时间线、过程线、证据
  → 冻结方案 或 受阻收尾
  → 用冻结方案连续起报
  → 只读评价与报告
```

创建任务时只填：

- `basin_id`
- `model_id`
- 日期范围与 lead 1/2/3
- 数据源与 forcing 模式（`F` 历史预报驱动 / `R` 理想气象回算）
- 基础方案
- 是否允许优化
- 预算上限（轮数、优化次数、墙钟、API）

缺目标不许猜，缺预算不许无限试。

## 4. 能力切片（按此顺序实现）

每一片的完成标准是：**有真实输入、真实产物、可复查账本。** 流程图不算完成。

### C0 数据与模型底座

把一个流域、一个模型跑出真实预报。

必须交付：

- 数据清单：流量、降水、蒸发/PET 或 OHN 所需气象、发布时间、合法切分
- 选定并锁定 XAJ 实现 **或** OHN 权重版本（先锁先跑通的那个）
- 一次真实 `forecast`：lead 1/2/3，带单位、时间、方案引用
- CPU 耗时与峰值内存记录；MPS 后验

OHN 额外：本机推理一次；若做适配，核验只更新了声明模块。

XAJ 额外：锁定变体、参数清单、暖机规则；蒸发皿 / PET / 实际蒸散发不得无依据互换。

**完成：** 命令或 API 对某个 `issue_time` 写出预报文件，数字可人工复核。

### C1 任务、方案与账本

没有 Agent 也能创建任务、保存方案、记下每次工具调用。

实体：

| 实体 | 作用 |
|---|---|
| Task | 配置、阶段、预算、终态 |
| Scheme | 模型 / Adapter / 参数或权重 / 配置版本 |
| DataSnapshot | 来源、处理、哈希、available_at |
| ActionRun | 谁调用了哪个工具、输入哈希、状态 |
| EvidencePacket | 观察、指标、Gate、产物引用、成本 |
| Forecast | issue/target/lead、预测值、方案与快照引用 |
| CostLedger | 墙钟、模型计算、API、峰值内存 |

**完成：** 手工调用一次检查或预报后，SQLite 里能按 `task_id` 把上述记录查全。

### C2 资料检查与修复

| 能力 | 做什么 |
|---|---|
| `data_check` | 文件、变量、单位、时间、缺测、重复、站点、发布时间、切分 |
| `data_repair` | 只修可追溯问题：补文件、单位、合法时区/日界线。保留原快照 |

正常极端值不得仅因“看起来异常”删除。修复后必须再检查。

**完成：** 人为制造缺文件或单位错误，系统能检出、修复、复检，并留下差异。

### C3 方案、状态与预报

| 能力 | 做什么 |
|---|---|
| `scheme_validate` | 读 Model Registry，确认 `model_id`、输入 schema、Adapter、阶段兼容 |
| `rebuild_state` | 暖机、窗口、缓存；XAJ 与 OHN 状态隔离 |
| `forecast` | 产出 lead 1/2/3，检查 NaN、时间、单位、文件完整 |

```python
forecast(scheme_id, basin_id, issue_time, data_snapshot_id) -> ForecastResult
```

**完成：** 同一方案、同一快照重跑，预报一致；产物缺字段时失败而不是静默写空。

### C4 有限优化与 Gate

可经 API 直接调用，不经过 Agent。

XAJ：

```python
calibrate_model(base_scheme_id, strategy_id, calibration_snapshot_id, validation_snapshot_id, budget_id) -> CalibrationRun
```

首期策略：`KEEP`、`CALIBRATE_BOUNDED`。

OpenHydroNet：

```python
adapt_model(base_scheme_id, strategy_id, training_snapshot_id, validation_snapshot_id, budget_id) -> AdaptationRun
```

首期策略：`KEEP`、`HEAD`、`STATIC`、`STATIC_HEAD`。候选空间冻结；一次调用内部可搜多个数值候选。

Gate（程序执行，不能被 LLM 绕过）：

1. 合法性：完整、无 NaN/Inf、时间单位、覆盖率
2. lead guardrail：不允许平均改善掩盖某一 lead 明显退化
3. 高流量 / 事件 guardrail
4. 主指标改善（例如三 lead NSE 等权）
5. 近似时优先 `KEEP`、更简单策略、更低成本

结果：`ACCEPT` / `KEEP` / `ROLLBACK`。优化器跑成功 ≠ 水文变好。

**完成：** 一次真实率定或适配；至少一次 Gate 失败并 rollback 到原方案；非目标模块 / 原参数未被偷偷改掉。

### C5 Agent Runtime

在 C2—C4 已可单独调用之后，才接编排。

```text
LOAD_STATE → AGENT_DECIDE → PERMISSION_GATE → TOOL_EXECUTE
    → NORMALIZE_EVIDENCE → UPDATE_STATE → FOLLOW_UP_GATE
         ↑                                      │
         └──────── needs_follow_up = true ──────┘
```

不要把 A01—A12 做成串行 Graph 节点。它们是 Router 里的可选动作。

Agent 每轮只选一个主动作。长数值搜索在 Tool 内完成。

`needs_follow_up = true` 需要同时：任务未终态、有新证据或必要未做动作、阶段允许、预算仍在、不是重复同一 hypothesis + action + strategy + base_scheme。

默认预算起点（产品安全阀，正式值可改配置）：

```text
max_agent_decision_rounds = 20
max_optimization_cycles = 4
OHN max_training_candidates_total = 6
same technical failure retry <= 2
```

优化预算跨 Agent 轮次共享，进程重启不清零。

**完成：** 存在一条真实轨迹：优化 → Gate 失败 → rollback → 下一轮换了动作或假设。TaskState 逐轮可回放。

### C6 工作台

前端不展示 A01—A12 复选框。

首期三个页面即可：

| 页面 | 内容 |
|---|---|
| 任务 | 创建、阶段、模型、预算、数据来源 |
| 运行 | 业务时间线、当前假设、下一动作、暂停/恢复；展开后才显示 round / action / evidence id |
| 结果 | 过程线、方案版本、Gate、采用/撤销、报告导出 |

时间线用业务语言，例如：正在检查资料、正在运行模型、候选因 lead 3 退化被撤销、维持原方案、已冻结、受阻。

**完成：** 不看终端也能跟完一次任务；数字与账本同源。

### C7 冻结回放与评价

| 能力 | 做什么 |
|---|---|
| `freeze_scheme` | 冻结模型、参数/权重、数据与预处理、窗口、Gate、预算 |
| `replay` | 按 `issue_time` 推进，只用冻结方案 |
| `evaluate` | 只读计算 NSE / KGE / MAE / Bias 等，出报告 |

阶段权限（产品规则，不是实验专用）：

| 阶段 | 允许 | 禁止 |
|---|---|---|
| B 构建 | 检查、修复、预报、诊断、优化、冻结 | 无限试参；改原始文件 |
| F 回放 | 取当时可得资料、固定转换、状态重建、技术恢复 | 按测试流量改参数、Prompt、阈值、策略 |
| E 评价 | 只读指标与报告 | 改已冻结结果 |

越权必须被执行器拒绝并记账，不能只写在 Prompt 里。

**完成：** 冻结后改配置无法在 F 生效；评价数字与预报文件对得上。

## 5. 动作目录（产品功能，不是流水线）

编号只用于 API、日志和权限。运行顺序由 Agent 或调用方决定。

| 编号 | 能力 | 阶段 | 所属切片 |
|---|---|---|---|
| A01 | 检查资料与预报条件 | B/F | C2 |
| A02 | 有依据补取或纠正 | B/F | C2 |
| A03 | 校验可执行方案 | B；F 只校验 | C3 |
| A04 | 重建起报条件 | B/F | C3 |
| A05 | 执行预报 | B/F | C3 |
| A06 | 诊断并建议下一动作 | B | C5 |
| A07 | 委托有限优化 | B | C4 |
| A08 | Gate：采用 / 撤销 / 继续 | B | C4 |
| A09 | 恢复、维持或受阻 | B/F/E | C5 |
| A10 | 冻结方案 | B | C7 |
| A11 | 连续起报 | F | C7 |
| A12 | 只读评价与报告 | B/E；F 仅摘要 | C7 |

必须能跑通的产品路径：

1. 正常：检查 → 预报 → 合法 → 冻结
2. 资料问题：检出 → 修复 → 再检查 → 预报
3. 优化失败：优化 → rollback → 换动作或停止
4. 调参无益：优化几乎无变化 → 停止，不继续刷
5. 能力不足：有限检查后 `BLOCK`，给出缺什么才能继续
6. 越权：F/E 调用 calibrate/adapt 被拒绝

## 7. 模型插件

两个 Adapter 平行，互不为子步骤。Agent 不能发明模型没有声明的能力。

```text
权限 = 模型能力 ∩ 当前阶段 ∩ 任务许可 ∩ 策略注册表 ∩ 剩余预算
```

```text
XAJ Adapter
  ├─ forecast
  ├─ validate
  └─ calibrate

OpenHydroNet Adapter
  ├─ forecast
  ├─ validate
  └─ adapt
```

日常 `forecast` 不得隐式训练或率定。

## 8. 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + ECharts |
| 后端 | FastAPI |
| 编排 | LangGraph（仅 C5 引入） |
| LLM | 直接模型 client 或 LangChain；C5 之前可以没有 |
| XAJ | 独立实现 + 率定器 |
| OHN | OpenHydroNet / PyTorch + 有限 Optimizer |
| 存储 | SQLite + 本地文件产物 |
| 执行 | 本地单任务，不并行训练 |

Tool 必须声明：输入输出 schema、允许阶段、模型能力、策略与预算、幂等键、失败类型、产物引用。相同 `tool + input_hash` 已成功则复用。

## 10. 产品完成门槛

首期产品算做完，当且仅当：

1. 至少一个模型，对一个流域，能真实 `forecast` lead 1/2/3
2. 资料错误能被检出并（在可修时）修复
3. 允许优化时，能跑一次真实 calibrate 或 adapt，Gate 失败会 rollback
4. Agent 接入后，至少一条多轮轨迹改变了下一动作
5. F/E 越权优化被后端拒绝
6. 工作台能跟完一次任务，数字与账本一致
7. `ACCEPT` / `KEEP` / `ROLLBACK` / `BLOCK` 都能作为真实终态出现

不要求：双模型都做完 O/P/A、预测统计显著、专家诊断正确率、业务减负证明。
