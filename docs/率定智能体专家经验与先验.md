# 率定智能体专家经验与先验

## 1. 为什么把外部 Expert Skill 纳入知识平台

公开项目、论文、教材和水文学家总结出来的率定经验，确实可以成为 Hydro-Agent 的“专家经验库”来源。但为了科研可解释性和后续工程可用性，本项目不把外部 Skill 文本直接当作已经验证的本地真理，而是分成三类知识：

```text
规范知识 Standard Knowledge
  └─ GB/T 等正式规则：具有规范性，进入确定性 Evaluator / Gate

专家先验 Expert Prior
  └─ 外部 Skill、论文、专家访谈：提供诊断与实验设计建议，仅 advisory

案例经验 Calibration Case
  └─ Hydro-Agent 在真实流域上运行得到的 Evidence：可形成正/负案例并持续验证
```

因此“别人的 Expert Skill”可以进入知识平台，但初始状态应为 `seed_prior`。只有经过本项目流域、数据和独立验证反复支持后，才允许升级为 `validated_local`。无论状态如何，Expert Prior 都不能直接修改 GB/T Gate 的规范结论。

## 2. 当前引入的第一批专家先验

本轮以 `zhuanglaihong/HydroAgent` 的 Expert Hydrologist 与 LLM calibration 思路作为方法启发，采用本项目自己的结构和表述重新实现，没有复制其源码或 Skill 文本。其许可证为 PolyForm Noncommercial License 1.0.0，因此仓库中明确记录 provenance 和 `conceptual_reimplementation_no_source_copy` 策略。

当前种子规则包括：

1. 水量平衡优先：当 PBIAS 明显偏离时，优先检查/率定蒸散发与产流过程，不先精调汇流；
2. NSE 为负时先检查数据、时间、状态和 forcing，不把所有问题都解释为参数问题；
3. 参数触边界首先视为诊断证据，不自动扩大参数范围；
4. 若只触及局部搜索窗口、而老师/内核绝对参数范围仍有空间，可逐级放宽下一轮搜索窗口；
5. 若已经触及绝对参数边界，则禁止继续外扩，应优先把它当作数据、状态、过程假设或模型结构的诊断信号；
6. 率定期改善但独立验证退化时不能宣布成功；
7. 多轮受控实验无改善时，应降低继续扩大搜索的优先级，并考虑模型结构；
8. 流域属性可以形成搜索先验，但不能替代观测 Evidence。

这些规则存放于：

```text
src/hydro_agent/knowledge/data/expert/hydrologist-calibration-priors-v1.json
```

## 3. Basin Hydro Profile

流域画像属于“数据底板 → 知识平台”的桥梁。V1 只自动推导定义清楚且单位可审计的指标：

```text
Aridity = ΣPET / ΣP
Runoff Ratio = ΣQ_depth / ΣP
```

并且只允许使用验证期之前的数据生成画像，避免 held-out validation 泄漏。真实 Workbench 的 A06 诊断也已经改为只使用验证期开始前的历史预报/观测，不再从 held-out validation 窗口取误差信息进行率定决策。

对于蒸发数据，只有在来源元数据明确为潜在蒸散发（PET）时才计算 Aridity。老师腰古资料中的旧字段虽然叫 `pet_mm_day`，但来源语义是实测蒸发，因此不会被错误地用于计算干旱指数。

暂不自动生成 BFI、积雪比例和气候区，因为这些需要明确的数据源、计算方法和验证过程。以后可以接 CAMELS/Caravan 静态属性或经过审核的确定性算法。

## 4. Expert Prior 如何进入率定闭环

```text

      │

      │
      ▼

      │
      ├─ 误差诊断规则
      ├─ 流域先验
      └─ 搜索/反思经验
      │
      ▼
Calibration Scientist
Observe → Diagnose → Hypothesis → Plan
      │
      ▼
CalibrationPlan
(parameter groups / objective / optimizer / budget / knowledge refs)
      │
      ▼
SCE-UA → XAJ
      │
      ├─ objective / trace
      └─ search-boundary evidence
      │
      ▼

      │

```

其中 Expert Prior 只能影响 `CalibrationPlan`，例如将“全参数 + NSE”收敛为“evap/runoff + composite”；具体连续参数仍由 SCE-UA 搜索。

### 4.1 参数触边界时怎么处理

SCE-UA 运行后会记录候选参数与本轮搜索边界的关系，并把触边界分成两类：

```text
local boundary hit
  = 候选靠近当前局部窗口边缘
  + 老师/内核绝对范围外侧仍有空间

absolute boundary hit
  = 候选已经靠近老师/内核绝对参数边界
```

这两类证据的处理不同：

```text
local hit
  ↓
Expert Prior: 可在 absolute bounds 内逐级放宽
  ↓
0.35 local window
  → 0.65 broadened window
  → global absolute window

absolute hit
  ↓
Expert Prior: hold_absolute_bounds
  ↓
禁止自动继续外扩
  ↓
作为数据/状态/机理/结构诊断证据
```

因此系统不会把“优化器压边界”简单理解为“范围不够大”。搜索空间的变化本身也是一个可审计的科学决策。

## 5. 从“别人的经验”变成“我们的经验”

知识成熟度建议固定为：

```text
external / literature heuristic
        ↓
seed_prior
        ↓ 真实流域实验
supported_prior
        ↓ 多流域重复验证
validated_local
        ↓ 若被反例推翻
retired / scoped
```

每条规则至少保留：

- `rule_id`
- 来源与许可证
- 适用对象/模型
- 状态
- 触发信号
- 推荐动作
- 实验支持/反例
- 版本

这样未来老师给出的经验、预报员访谈、论文知识以及其他开源 Agent 的 Expert Skills 都可以进入同一体系，而不会和正式规范或本项目真实案例混在一起。

```text
O  原始参数
P  固定 SCE-UA
A0 Calibration Scientist + SCE-UA
A1 A0 + Expert Prior

```
