# 文献对照与人工减负可行性审查

审查日期：2026 年 9 月 7 日。对象：河海大学数字孪生卓工班（二期）“基于智能体的水文预报方案构建及参数优化”现有三份设计文档。指导教师信息沿用项目资料：方园皓副教授。

本文为设计审查和实验建议，不表示系统已经实现，不表示已获得减负效果。本次不修改主方案，不编写 Agent Skills。

## 1. 审查结论

**课题值得继续，工程应用价值比当前的方法原创性更明确。最有说服力的目标，是在预报质量和任务完整性满足约束的情况下，减少人员主动操作、重复检查和异常处理的总负担。**

本次检索已经发现直接覆盖 LLM 水文率定、端到端建模，以及“预报员经验—Skills—洪水预报流程”的研究。不能再把首次采用 Agent、LangGraph、Skills 或自动调参作为创新主张。把模型换成 Google OpenHydroNet、把系统放在 M1 Pro 上运行，也不能独立构成方法创新。

作为卓工班工程课题，可将贡献定位为：针对公开数据和有限算力，建立可复现的预报工作自动处理系统，并通过真人对照与固定自动化对照，回答哪些人员动作能够可靠接管、哪些动作容易增加返工、收益在什么条件下成立。能否形成学术上的新方法，还取决于动作决策机制和实验发现，不能在设计阶段先下结论。

## 2. 检索范围与证据边界

检索方向包括：水文 LLM 智能体与自动率定、预报工作流与 Skills、人工预报员价值，以及自动化的人工负担评价；沿相关论文引用追踪邻近工作。主要使用出版社论文页面、arXiv、NOAA 学术存档及作者代码仓库。Semantic Scholar 两次公开 API 查询均返回 429，未作为完整文献库来源；Crossref 成功核对 HydroCraft 元数据，另一次请求限流。

这是一轮定向文献审查，不是穷尽式系统综述，也不构成“尚无人研究”的查新证明。以截至审查日可检索的材料为依据。下表区分正式期刊研究、评论、预印本与代码材料；阅读范围不足的条目不用于强定量结论。不同作者使用 HydroAgent / Hydro-Agent 同名，不应视为同一个项目。

### 3.1 最需要先读的三篇

**Yang2026Skills：** 已核对正文方法与讨论，其框架设有专家审核节点，主要实验集中在前期研判，并明确后续仍需实际业务验证。论文中的 LLM 运行时间、API 费用不能直接当成人工工时节约。本项目若研究限定任务内减少逐轮干预，应把差异落到完成率、误处理、复核与返工的实测结果；不能只删除审核按钮就声称创新。[论文](https://arxiv.org/abs/2607.23983)

**Zhu2026Calibration：** 已核对正文。其主要比较涉及率定质量及求解效率，研究显示不同 LLM 表现并不一致。对我们的启发是保留强优化对照，并把数值搜索和人员劳动分开计量。[论文](https://doi.org/10.1029/2025GL120043)

**Yan2026Agent：** 已核对出版社摘要、方法相关页面及可用性声明。案例同时揭示气象驱动错误可以使预报失败。流程自动跑完不等于预报可用，也不证明人工成本一定下降。[论文](https://doi.org/10.1029/2025GL119814)

## 4. 对现有设计的具体评价

### 4.1 已经走对的地方

- 从人员工作推导 A01—A12 动作，而非先规定几个 Agent，是合理的需求设计。
- 把数据纠错、起报条件重建、模型微调分开，避免所有错误都通过调参“修好”。
- 有正常不干预、候选撤销、预算停止和失败结论，适合检验实际自主处理能力。
- 开发优化、冻结测试和事后报告分离，保留了可评价的时间边界。
- 二维过程线、动作证据和成本记录比装饰性的三维仿真更贴合本期问题。

这些是方案质量与可复现性的优点，不应一概包装成学术首创。

### 4.2 仍然不足的地方

**第一，人工减负目前还不是主实验。** 现有方案较详细地规定了 NSE 和微调预算，但尚未规定谁来做人工对照、主动工时怎样计量、Agent 失败后的返工算给谁。仅统计工具调用次数和人工提示次数，无法证明减少人工成本。

**第二，水文诊断与 OpenHydroNet 可操作变量之间仍有断层。** 人员判断“洪峰偏低”不能直接推出“提高学习率”或“多训练三轮”。LSTM 的模块不是产流蓄水或河道汇流参数。A06—A07 应检验诊断是否帮助排除错误措施、减少无效试验；不能凭一段通顺解释认定理解了水文机制。

**第三，目前更容易实现的是流程自动化和技术恢复。** 单位核查、文件补取、历史窗口重建与报表生成很有用，但若所有案例都只有这些问题，项目证明的是水文任务的软件自动化。需要加入真实预报误差、证据不足和无需处理案例，才能评价领域判断。

**第四，不能把人工基线设成完全手工操作。** 人员也能使用批处理脚本和自动优化。公平的问题是：在相同工具条件下，Agent 还能减少多少人员协调与排障工作？

**第五，缺少专家经验来源。** 团队尚无水文建模经验，Skills 不宜完全由 LLM 自行编造。需要将少量真实案例中的“看了什么、排除了什么、为什么采取动作、何时停止”形成专家核对记录。无需让导师为每次运行把关，但需要在设计和评价阶段提供有效依据。

**第六，日尺度任务与洪水预报表述需要一致。** 现有范围可以研究未来 1—3 日流量和高流量事件，不能据此声称解决小时级突发洪水洪峰或淹没预警。若取得的气象资料只适合回算，应继续明确标注实验性质。

## 5. 哪些工作最有可能减少人工

以下是待验证的工程判断，不是已经测得的收益。

| 工作 | 对应动作 | 预期减负方式 | Agent 必要性及主要限制 |
|---|---|---|---|
| 资料到齐检查、变量单位和时间对齐 | A01—A02 | 少翻文件、少重复核对、自动补取有来源的资料 | 固定检查用代码即可；Agent 价值在组合证据、决定下一条排查路径 |
| 初次配置与小样本试运行 | A03 | 少查接口和反复试错，复用已验证方案 | 一次性收益需与长期运行收益分开；不能无限生成未经验证配置 |
| 历史条件重算、任务异常恢复 | A04、A09 | 少盯运行、少手动重启和接续 | 常见重试由程序处理；超出已知模式的恢复选择才值得调用 LLM |
| 误差排查与决定是否适配 | A06—A08 | 缩小排查范围，减少无意义试验 | 最有领域研究潜力，也最容易误诊；需要专家核对及动作结果验证 |
| 日常起报与结果归档 | A05、A10—A11 | 减少重复启动、导出和版本整理 | 调度与归档本来可自动化；必须对比固定流水线 |
| 多轮结果比较、失败归纳和图表报告 | A08、A12 | 少搬数字、少整理过程线和实验记录 | 数字由程序生成，文字必须关联证据；人工审阅时间计入成本 |

优先完成三条有业务意义的路径：资料异常的追查与恢复；连续预报误差的诊断与有限试验；结果对照、撤销和报告收尾。正常数据与正常预报应能直接通过，不为了展示智能而多做动作。

## 6. 建议收紧的研究问题

建议保留正式课题题目，增加定位说明：

> 面向日尺度水文预报重复作业与异常处理，研究基于业务处理动作的自主智能体方法，在相同数据、工具及资源约束下，评价其对人员主动工时、处理正确性和预报质量的影响。

可验证的问题有三个：

1. 与人员使用同样工具相比，Agent 能否降低完成同一合格任务所需的主动工时？
2. 与固定自动化流程相比，Agent 是否能在异常和多种可能原因并存时提高正确完成率，减少人工接管？
3. 加入经核对的业务动作知识后，相比通用 LLM 调用相同工具，是否减少错误动作、无效重试和结果复核负担？

这三个问题分别检验减负价值、自主判断价值和领域知识价值。它们是本项目的研究假设，不是本次检索已证实的全球空白。

## 7. 适合当前资源的对照实验

### 7.1 三个主组，一个可选消融组

| 组别 | 工作方式 | 用于回答 |
|---|---|---|
| H：人员＋共同工具 | 人员可用同样的数据检查、模型运行、优化及绘图程序 | Agent 是否减少人员总劳动 |
| P：固定自动化流程 | 同一套工具、已有质量规则、重试与固定优化策略；例外交给人员 | 超过常规自动化的收益有多少 |
| A：业务动作 Agent | 读取证据、自主选择允许动作、验证并收尾，使用同样工具 | 自主处理在质量约束下是否有效 |
| A0：可选消融 | 同一 LLM、同样工具和预算，仅移除专门的业务动作指导，保留公共技术校验 | 收益是否来自业务知识，而非单纯多调用 LLM |

H/P/A 是核心。Optuna 作为共同数值工具或单独微调对照即可，不必把完整人员实验扩张成五六组。各组使用相同数据修复结果、模型起点、允许信息和计算额度；若比较修复能力，则在匹配的异常输入上单独评价恢复，不混入模型优越性结论。

### 7.2 任务集合

先以一个流域完成小型探索试验，建议准备 12—18 个任务包，覆盖正常运行、资料问题、运行异常、预报偏差和证据不足五类。该数量是工作量起点，不是统计学充分样本量。

任务包可包含若干连续起报日，并有明确开始条件、允许信息、验收产物和时间预算。真实历史问题与人工注入故障分别标注、分别报告，不能把注入故障比例当成业务发生率。错误来源与正确处理路径由评价者保存，不提供给被测系统。

模型误差案例中包含相似症状、不同原因的情况；若观测证据无法唯一判因，正确结果可以是保留多个假设、停止无效适配或请求接管。不能要求 Agent 猜中预设故事。

Agent 的随机性可先在代表任务上重复 3 次，预算依据本机实测确定。对于可缓存的相同模型计算，各组采用相同缓存政策；模型原始耗时和实际执行耗时分别记录，避免把缓存收益记成推理收益。

### 7.3 真人对照与专家核对

先用熟悉操作程序的参与者做先导试验，不将其当成熟练预报员。向所有参与者提供同样培训与资料，采用难度匹配的不同任务，交叉平衡工具使用顺序，避免做第二遍天然更快。

记录每人的熟悉度、工作阶段和任务结果；多人做同一任务不是多个独立水文事件，同一人多次操作也不是多个独立参与者。样本少时报告逐例结果、配对差值及分布，不贸然宣称普遍显著。

如参与者只有学生，结论限定为降低学习者或模型使用者的操作负担。若要说减少专业水文人员成本，需增加熟练人员参与。建议请导师或其指定人员核对 3—5 个典型业务案例及最终产物评价规则；这只是知识来源起点，不足以单独证明行业普适性。

### 7.4 指标与核算

**主指标：每个任务的人员主动工时。** 包括准备输入、理解提示、检查输出、处理失败、人工接管、修订报告和最终核验。计算等待单独计时；等待期间确实需要人员监视的部分计入主动劳动。并行工作不能重复累计同一人的工时。

设 H 为人员基线主动工时，A 为 Agent 流程中人员主动工时，探索性节省率为 `(H − A) / H`，H 为零时不计算比例。配对任务先报告分钟差，再报告总体分布。未完成和错误完成均保留，额外报告全任务总成本及合格完成率，避免只挑成功案例算节省。

其他必要指标：

- 合格任务完成率、无需中途接管的合格完成率、接管次数及接管原因。
- 错误动作请求率、被工具拦截率、实际造成错误修改率，三者分开。
- 正常情况下不必要干预率；不能仅追求执行动作数量。
- 各预见期的 NSE/KGE，以及按预先定义事件计算的峰值偏差、日尺度峰现误差、洪量偏差、漏报和误报、输出覆盖率。
- 端到端历时、模型计算时间、LLM 请求次数及实际 API 费用。
- 可选简短主观负担问卷；不以主观“感觉快了”替代计时。

减负结论须同时满足事前规定的质量与完成率约束。质量容忍差和最低完成率由先导试验与导师意见确定，在正式比较前冻结；不能事后选择对 Agent 有利的指标。小样本通过经验门槛，只能称为探索性结果，不能冒充正式非劣效统计证明。

货币总成本应包括 `人员主动时间 × 人工单价 + API + 计算 + 分摊维护成本`。人工单价暂未确定时先报告分钟和实际费用，后续做不同单价、任务频率下的敏感性分析。若考虑一次性开发投入，额外开发成本除以每次任务净节省成本，可估算回收所需次数；单次净节省不为正时没有此意义下的回收点。

## 8. 需要如何调整设计，而不是继续加功能

1. 将“质量约束下减少人员主动工时与重复劳动”提升为主目标，预测精度是必要约束和独立报告项。
2. 补一张“任务—人员原操作—Agent 动作—验收证据—主动工时”的表，贯穿日志、网页和实验。
3. A06 输出诊断假设、支持证据、替代解释、下一项检查及停止条件；不要求披露内部思维链，也不把自报置信度当成经校准的可靠性。
4. A07 的启用依据必须可验证；先证明不会把输入错误当成模型问题，再研究是否更省试验。不能为频繁调参而调参。
5. Skills 的内容来自核对后的动作案例和可执行工具，按需加载；LangGraph 负责状态、恢复和预算。这些作为实现机制，不列为独立创新。
6. 日常正常处理可以全自动；超出证据和工具能力时，Agent 自主给出受阻结论并保存现场。无需逐轮用户指令不等于不需要一次性任务配置，也不等于必须自动猜测未知事实。
7. 网页首页突出待处理问题、当前预报、自动完成事项和需接管事项；答辩核心图增加人员工时分解、完成率—人工负担对照及错误处理案例。

## 9. 失败实验同样应该有明确结论

| 观察结果 | 可支持的结论 | 不能支持的结论 |
|---|---|---|
| 预报精度相近、主动工时下降 | 在该任务集上有减负价值 | 全面优于专家 |
| 优化次数减少、复核时间上升 | 求解过程更短，人员净收益未成立 | 降低人工成本 |
| 固定流水线与 Agent 相当 | 所测任务主要依赖常规自动化 | Agent 必然优于规则 |
| Agent 能恢复注入故障、真实误差处理较弱 | 技术恢复能力成立，水文诊断仍不足 | 已接管水文专业判断 |
| 正常任务频繁额外调整 | 自主干预策略引入不必要成本 | 多试几轮就是智能 |
| 无法获取合法未来气象或权重存在时间重叠 | 数据/模型条件限制了预报评价 | Agent 预报性能差或好 |
| 故障无法修复但有依据地终止 | 边界识别与收尾能力可成立 | 预报任务成功完成 |

## 10. 供导师讨论的简短表述

本课题拟在公开数据和有限算力条件下，以 OpenHydroNet 为计算基础，研究智能体对日尺度水文预报重复作业和异常处理的自动承担能力。已有文献已探索水文 Agent 率定、全流程建模及 Skills 化预报员经验，因此本项目重点放在可验证的人员减负：在相同工具、数据及资源约束下，对比人员操作、固定自动化与业务动作 Agent，测量主动工时、接管与返工、处理正确性和预报质量，形成适用范围及失败结论。项目以工程验证为首要目标，不预先承诺替代专家或优于传统优化。
